## 训练口径（2026-09-19 用户定，这就是"英雄特化"怎么训）

> 用户原话：「被训练的队伍用噩梦+最新权重，陪练队伍用噩梦+上一个权重。只要最新的权重对上一个权重胜率能不断增加，
> 最终到达一个边界，是不是就能找到相对更强的权重？还有你训练某个英雄的时候，其他英雄不要被正在训练的权重影响了，
> 要控制变量」「为什么要那么多种子？**以测试权重和不同队伍为主**啊。其他几个英雄训练起来」

| 要素 | 做法 | 为什么 |
|---|---|---|
| 上一代 | `RL/weights/英雄世代.json` = 当前生产 `噩梦.json`（**通用键 + `hero_XX` 英雄段**，2026-09-20 并档后是同一份文件） | 起点必须是"线上现在跑的"，否则不算改进 |
| 候选 | 上一代 + **一个英雄的若干键**（一次一个臂） | 单变量：其他英雄一个键都不动 |
| 陪练 | 上一代**本身**（`league.checkpoint` + `self_play_fraction=1.0` → harness 的 `wB` 通道） | 用户口径的"新 vs 旧" |
| 盘面 | **镜像同队伍**（双方同一支队） | 双方唯一差别就是那几个键 |
| 队伍 | **多支**（每个臂在 3~6 支不同队伍上各打一遍） | 用户口径：看的是"换队伍还成不成立"，不是堆种子 |
| 指标 | 生产侧（`a_side=1`）胜率 + **配对 Δpts**（同 种子×先后手×队伍，臂 − 恒等对照臂） | 绝对分会被"这批种子整体偏难"吞掉，配对差才是键的效果 |
| 判定 | 跨队伍都对上一个权重更高 ⇒ 接受；接受后覆盖 `英雄世代.json` 的对应英雄段，成为下一代 | 世代滚动，胜率不涨就到边界 |

工具：`RL/train/英雄特化搜索.ps1`（单英雄单轮：`-Hero -Decks -Arms -Seeds -Tag`，多臂并排 = 完全配对）·
`RL/train/英雄特化_批跑.ps1`（总驱动：矿工 6 队复验 + A 档四个英雄各 3 队）。
⚠️ 跑训练期间**别改 `src/BattleAI.gd`**：fork 脚本哈希一变，冻结守卫会拒绝把两批结果并进同一份 `measure.csv`（这是设计，不是 bug）。
