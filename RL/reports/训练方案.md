## 1. 方法：坐标上升 + 「粗筛/确认」两段制

**为什么必须两段**：本项目已**三次**实证"赢家的诅咒"——坐标上升 +0.19/+0.25、
规则 B +7.92、`HP_VALUE_W` +10.93，**全部在换种子后消失**。所以：

> **入选规矩：一个改动必须跨 ≥2 个独立种子块合并后 95% CI 仍不跨 0，才写进 `噩梦.json`。**

每一轮：

1. **粗筛（64 对/臂 = 16 种子）** —— 只用来**淘汰**明显更差的臂，**绝不选冠军**。
2. **确认（128~256 对/臂 = 32~64 个"新"种子）** —— 只带粗筛里"方向为正"的 2~3 个臂。
3. **合并判定** —— 把该改动**历史上所有轮次**的同类改动做逆方差加权（n/sd²）合并；CI 不跨 0 才接受。
4. **接受即落盘** —— 写进 `RL/weights/噩梦.json`（只写"与困难档不同的部分"），并记 `RL/reports/训练日志.md`。
5. **停止准则** —— 连续 **2 轮**没有任何臂通过第 3 步 ⇒ 判定"权重已到顶"，转 §4 的其它路径。

## 4. 若权重调参到顶（很可能，见下）—— 转向"非权重"的提升

⚠️ **必须说清的天花板**：留出集是 **96 局**，Wilson 下界 > 0.5 需要**实测胜率 ≥ 58/96 = 60.4%**。
而权重层实测的单键效应多在 **±5~10 分/局**（折合胜率几个百分点）⇒ **只靠 7 个权重键几乎不可能到 60%**。
所以权重调参是"**必要但不充分**"，并行/接续要做这三件（都不占训练维度）：

1. **英雄特化（原目标③）**：走 `HERO_hero_XX_*` 扁平通道 → 落成 `hero_XX` 段（噩梦+ 用）。
   先从"有明确机制、且通用权重表达不了"的英雄开始（例：`hero_42` 金矿已成先例；`hero_23` 复仇者、`hero_48` 未移动得坚固、
   `hero_10` 白游侠散射）。
2. **规则改进（规则 A/B/C 重做）**：
   - 规则 B：现在"阈值 4"判噪声、且让搜索变慢（O(单位²)）⇒ 改成"每局面算一次敌人可达格集合"复用，
     并只保留**路网躲避**那一项重测；
   - 规则 A：现在只在"分数差 < 0.5 的并列"里裁决 ⇒ 影响面太小；若要让"合力可杀"真正生效，
     应升级成**显式加分项**（`合力可杀 + net 为正` → 加分），代价是新增一个键；
   - 规则 C：实测 sd 0.03（几乎不触发）⇒ 只在"替补频繁"的模式（4v4？）里才有意义，暂缓。
3. **难度/算力旋钮**：验收时对手用 `beam_opp=800`、候选用 `beam=1200`（spec 的默认口径），
   而训练期用 400/100 —— **验收前必须按 `phases` 的验收档重跑一遍**，否则结论不可比。

## 5. 验收（只在最后做一次）

1. **对拍/正确性**：`--check-only` ×4 + `技能对拍 plancore`（4 个身价数值逐字不变）+ 8 局冒烟 —— 已全部通过，验收前复跑一次。
2. **留出集**：24 种子 × 4 = **96 局**，`opp=base`、候选 `beam=1200`、对手 `beam_opp=800`；
   报 **胜负 + Wilson 95% 区间**，判据 = **下界 > 0.5**。
3. **对照基线**：同一批留出集上跑"困难档 vs 困难档"（= `p1_base` 之类）作为噪声地板。
4. **人工**：你在游戏里选「噩梦」打几局；满意后再决定是否把某个值同步进生产三档（**那一步单独确认**）。

## 6. 每次训练必须遵守的几条（防坑清单）

- **不许用留出集做任何选择**（只在最后 96 局用一次）。
- **64 对只做淘汰**；选冠军必须换新种子 + 合并 ≥2 块。
- **改了哪怕一个键，就要重跑 `-Task gen`**（候选权重文件带 `_rl_base_sha12`，防止拿旧文件当新臂）。
- **每次 run 前看 `[spec]` 行的 `overlap=0 lineup_overlap=0`**；扩种子池会触发 `LINEUP SPLIT VIOLATION`（本轮已踩过一次）。
- **行为零变化优先**：新增/精简键一律"默认关闭/默认值不变"，生产三份 sha 必须保持 `2c2edab3b262` / `460496bbd672` / `bd67075ab80b`。
