## 1. 【用户那条 DIFF】每回合状态没进 sim —— 已修

**真实侧**：`Unit.counter_used_this_turn` 等每回合状态由真实盘面持有；赏金猎人本回合**已经反击过** →
`Battle._apply_attack` 的 `can_counter` 判定 `not target.counter_used_this_turn or …infinite_counter()` 失败
→ 鼠队长那一击**拿不到反击**（真实 0 伤害）。
**模拟侧**：`build_state` 不读这三个标志 → 每招从真实盘面重建 sim 时"已反击过"丢失 → 模拟以为还能反击 → 多扣 1 点。

改动（fork `build_state`，全部 `d.get(…, false)` 缺省）：
```gdscript
u.moved        = bool(d.get("moved", false))
u.attacked     = bool(d.get("attacked", false))
u.counter_used = bool(d.get("counter_used", false))
```
harness 侧：`_build_sim` 从真实单位把三者注入 descs；场景可加 `counter_used/moved/attacked: true` 强制。

**新场景 + 消融**（`RL/reports/b4_hero_04.log`、`abl3_hero_04.log`）：
```
修复后：hero_04·每回合状态·对方已反击过|MATCH|鼠队长 15/18 不变（没有反击）; 目标 40/40→36/40
        hero_04·每回合状态·复仇者已反击过仍反|MATCH|鼠队长 15/18→11/18（复仇者 infinite_counter 例外仍成立）
消融（不注入 counter_used）：hero_04·每回合状态·对方已反击过 真实=15/18 | 模拟=13/18  ← 与用户那块同形
```
注：`moved`/`attacked` 的可见影响只在 `_actions_for` 的**候选生成**（矩阵的强制动作绕过它），
所以矩阵只能观测 `counter_used`；三者一并注入是为了"sim 状态忠实"（RL/规划路径用得到）。

## 2. 【新场景顺带挖出的真缺口】锤头鲨(hero_37) 的记账口径

新加的阵容场景 `阵容·同阵营锤头鲨见证`（X 之外再放一只**同阵营锤头鲨见证者**）先报了两条 DIFF：
```
hero_32·阵容·同阵营锤头鲨见证：真实见证者 eatk 2→3 | 模拟停在 2     （长角自己结算伤害那条路漏账）
hero_46·阵容·同阵营锤头鲨见证：真实见证者 eatk 2→4 | 模拟只到 3     （主伤害 + 附体镜像各一次）
```
真实规则（`heroes/hero_37_锤头鲨.gd::on_someone_damaged`）：`target.faction == unit.faction → return`、
`target._was_counter_damage → return`、`side_faction(active_side) != unit.faction → return`
→ **"本回合内每一次敌方单位受伤，己方每只锤头鲨各 +1 攻"，与伤害来源无关**（AOE 每个受击目标各算一次）。
模拟原来只在"主动攻击的主伤害"那一步 +1 → 长角自结算伤害、附体镜像、散射/剑气/击退伤害、烛火灼烧、
末日、落停引爆全都不计。
修法：把记账挪到**统一伤害出口** `_sim_take_damage`（新增 `counter` 形参，反击路径传 true），
`_sim_hammerhead_bump()` 判 `v.fn == sim.active_fn and t.fn != v.fn` + 非反击 ✓。修后 7 个抽样英雄全 `diff=0`。

## 4. 矩阵阵营维度：结论 + 清单 + 成本

**结论：被测英雄 X 恒为 E 方（`const E := 1`，所有通用场景都是 `"fn": E`）。** 变的只有 `active` 键（当前 1 条用 P）。
`heroes/*.gd` 里 faction 用法全扫一遍后分三类：

| 类别 | 英雄 | 是否需要"两方都跑" |
|---|---|---|
| **真正按阵营分流**（两侧行为不同） | **仅 `hero_35_炸弹人`**（单机 PLAYER=选格等真人 / 非 PLAYER=自动放；联机=只有本端阵营进选格） | 矩阵覆盖自动分支 ✓；**选格分支需真人交互 → 归检视器"交互接管"，不进矩阵** ✓ |
| 同阵营/敌对判定（对称） | hero_05 傀儡师、08 德鲁伊、11 塔盾、16 波盾、19 烈焰祭司、22 圣光、31 末日、37 锤头鲨、43 风语者、47 共鸣者 | **不需要**：同一段代码在两侧都跑，只有数据（谁是队友）不同；单阵营矩阵已覆盖逻辑 ✓ |
| 依赖"当前行动方"（不是阵营） | hero_22 圣光、hero_37 锤头鲨（`side_faction(active_side) == unit.faction`） | 靠 `active` 键：默认 E ✓ + `双队友·队友被攻击` 用 P ✓ → 两个方向都已覆盖 ✓ |

**补"另一方维度"的代价**：整体镜像 ≈ 用例翻倍（2026 → ~3900），全量一轮 ≈ 26 分钟（现在 ~14 分钟）、
单英雄 ≈ 7 分钟（现在 ~3.5）——**但产出极低**（唯一真分流的 hero_35 另一支需要交互）。
**建议：不要做整体镜像**；把预算花在**阵容维度**（同一个场景里放 2–3 个指定英雄）——本轮就是阵容场景
直接挖出 §2 那条真缺口，而阵营维度永远挖不到它。下一步值得补的阵容场景候选：`hero_47 共鸣者` 需要
**同阵营同名**才成立的账目（取和）、`hero_11 塔盾 + 被保护者` 的相邻组合等。
