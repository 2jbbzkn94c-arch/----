## 2. 炸弹"叠加罚分"是不是让 AI 过度保守？——结论：**不会，那个罚分现在是惰性的**

### 2.1 实验局面（`技能对拍.gd` 里临时加的 `bombdecide` 探针，已删）
D(2,3) 的 6 个邻居里 5 个用障碍堵死，只留 **(2,4)** 一个可站落点，并在 (2,4) 放一颗炸弹；
我方 hero_16（近战 4 攻）在 (1,4)，**一步**就能落到 (2,4) 并打 D。三种目标血量 = 秒杀 / 残血 / 满血。
每组打印：`search` 的选招、`_evaluate` 三个候选（什么都不做 / 落停炸弹格攻击 / 选招重放）。

### 2.2 数据（四组消融）

| 目标 | 罚分=8（当前） | 罚分=0 | 罚分=0 + 放开"炸弹不是落点"过滤 | 罚分=8 + 放开过滤 |
|---|---|---|---|---|
| 秒杀4血 | plan=`0:null:atk-2`；idle 13.56 / bomb 86.40 / plan 13.56 | **逐位相同**（13.56 / 86.40 / 13.56） | plan=`0:(2,4):atk1`；idle 13.06 / bomb 86.40 / **plan 86.40** | **与左列相同** |
| 残血6血 | plan=`atk-2`；11.06 / 26.69 / 11.06 | 逐位相同 | plan=`(2,4):atk1`；10.56 / 26.69 / **26.69** | 相同 |
| 满血40血 | plan=`atk-2`；-33.24 / -32.84 / -33.24 | 逐位相同 | plan=`(2,4):atk1`；-33.74 / -32.84 / **-32.84** | 相同 |

日志：`bomddecide_pen8.log` / `_pen0.log` / `_nofilter_pen0.log` / `_nofilter_pen8.log`

### 2.3 结论与依据（代码路径）
1. **罚分 8 与 0 的四组结果逐位相同（连分数都一样）→ 这个固定罚分对选招完全不起作用。**
   原因：落停引爆建模后，`_apply` 会把该格的炸弹 **`erase`** 掉；而罚分的条件是
   `sim.bombs.has(bu.cell)` —— 落停那一下炸弹**已经不存在了**，所以"自己选择踩上去"这条路永远命中不了罚分。
   它唯一能命中的是"**被强制位移到炸弹格、而炸弹还在**"的状态（击退/换位/拉人/暗域占格——这些路径**还没有**引爆建模）。
   反证"罚分本身是活的"：人工把炸弹塞到某我方单位脚下时它确实扣分 —— `SK|BOMBPEN2|unit=独脚龟 delta=-8.00`（批次4）。
2. **所以不存在"爆炸伤害 + 固定罚分"双重计价导致过度保守**：两者的生效条件互斥（炸弹被引爆即消失）。
3. **真正的"闸门"在候选层而不是评分层**：`_move_cells` 里"非免疫单位不把炸弹格作为落点"的 `safe` 过滤。
   把这一层放开（实验 3/4 列）后，AI **会**主动选"踩炸弹收人头"：`plan=0:(2,4):atk1`，
   评分 86.40 vs 不动的 13.06（**+73.3**），而且在罚分 8 / 0 下选的**一模一样**。
   → 换句话说：现在 AI 放弃"5 血换一个人头"不是罚分的锅，是它**根本不考虑**落在炸弹上。

### 2.4 建议（**由用户决定改不改**，我没有留下任何改动）
- **(a) 罚分可以归零**：`BOMB_STAND_PENALTY` 对选招没有任何可测影响（4 组数据），可视为冗余；
  若要留保险，建议 ≤2 且明确只针对"被强制位移后站在炸弹上"。
- **(b) 更值得补的是那条真缺口**：`_trigger_bomb` 只补了"移动落停"这一条路，
  击退/换位/拉人/暗域占格落到炸弹格时真实也会引爆（`Battle._trigger_bomb`），模拟还没有。
  这正是当年那个固定罚分在替它兜底的地方；补完之后罚分可以彻底归零。
- **(c) 若希望 AI 能权衡"踩炸弹换人头"**（上面那个 +73 的局面）：要放开的是 `_move_cells` 的 `safe` 过滤。
  这是行为取向（要不要冒险）而不是保真问题——建议单独作为一个策略开关，别和保真修正混在一起。
