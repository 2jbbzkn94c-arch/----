# 对手反击一层（`REPLY_TOPK`）设计与算力预算（2026-09-18）

> 用户第 2 条：「本回合输出与下回合被输出达到一个**最优平衡**」。
> 现状：`search()` **只搜自己这一回合**（`src/BattleAI.gd:641-680`），对玩家的估计是**静态启发式**
> `_incoming_damage_on()`（="假设玩家所有够得着的人都打我，我挨多少"），**不是"玩家的最优回应"**。
> ⇒ AI 会走出"当场很赚、下回合被打死"的线路，而人类一眼能看出来。

## 一、为什么不放在 `_evaluate` 里

`_evaluate` 在束搜索里被调用**几十万次**（每回合 10^5 量级）。若在它里面做对手推演，成本要乘 K 倍 ⇒ 直接爆炸。
⇒ **放在搜索收敛之后**：对**最终候选态的前 K 条**做一次反击推演，重新排序选最终方案。

## 二、算法（对手"贪心一层"，不做完整极小极大）

```
search() 收敛 → 取 top-K 终局态（K = REPLY_TOPK，建议 8）
for 每个终局态 st:
    base = _evaluate(st.sim)
    worst_drop = 0
    for 每个**尚未行动的玩家单位** u:            # 通常 0~3 个
        best_for_me = +inf
        for 玩家 u 的每个候选动作 a in _actions_for(st.sim, u):   # 走位 ≤ MAX_MOVE_OPTIONS+4，攻击目标 ≤3
            s2 = st.sim.clone(); _apply(s2, u, a)
            d = _evaluate(s2) - base              # 我方视角：降得越少越"对我好"
            best_for_me = min(best_for_me, d)     # 玩家会挑**对我最不利**的那一手
        worst_drop += best_for_me
    reply_score(st) = base + REPLY_W × worst_drop
最终选择 = argmax reply_score
```
**语义**：`REPLY_W = 0` ⇒ 退化成现状（只看本回合）；`REPLY_W = 1` ⇒ "把对手的最优一手也算进这一手的账上"。

## 三、算力预算（按实测数字推）

| 项 | 数量 | 单次代价 | 小计 |
|---|---|---|---|
| top-K 终局态 | 8 | — | — |
| 每态玩家单位 | ≤3 | — | ≤24 |
| 每单位候选动作 | ≤约 50（走位候选 `MAX_MOVE_OPTIONS+4` = 20，加上可打目标 ≤3、清障/吃矿等） | — | ≤1200 次 `clone+_apply+_evaluate` |
| 单次 `clone+_apply+_evaluate` | — | 约 20~60 µs（`Sim.clone` 是轻量结构复制，`_evaluate` 是纯算术 + 少量缓存查表） | **约 25~70 ms/决策** |

对比现状：单次决策实测最坏 **2438 ms**、搜索预算 `time_budget_ms` 默认 2000 ⇒ **加一层反击只占 1~3%**。
⇒ **这是"性价比最高的一块"**：不用先做提速也能上（与 §14#104 里"Depth=2 要先提速"的判断相比，这里因为只对 top-K 做、且对手只贪心一层，成本可控）。

## 四、落地形式（与现有纪律一致）

- **新键两个，默认关**：`REPLY_TOPK`（0 = 关；建议扫 0/4/8/16）· `REPLY_W`（默认 1.0）。
- 放进 `Get-RuleScoreKeys`（不进自动搜索、可显式点名、进权重指纹）—— 与 `TERMINAL_W`/`RISK_W` 同款。
- **默认关 ⇒ 生产三档逐位不变**（照旧跑 `inertchk` 那套逐位验证）。
- 需要新增一个函数 `_worst_reply_drop(sim) -> float`（约 30 行），不改 `_evaluate` 本体。

## 五、验收

1. `--check-only` 三份 0 问题 + fork 同步差异块 19/0 与 39/18；
2. **逐位不变**：`REPLY_TOPK = 0` 时同一批格必须逐字节等于改动前（用 `spec_inert` + `inertchk` 对照）；
3. **机制签名**（见 `RL/train/机制签名.ps1`）：开启后应看到
   · **我方阵亡数下降**（不再走进"下回合被打死"的线路）
   · **"被剃光头"（我方 3 人全灭）下降**
   · 平均回合数可能上升（更保守）或下降（更会抢先手）—— 两个方向都算合理，看胜率与阵亡数一起判；
4. 跨队镜像（≥4 队）的胜率 > 0.5 才算"有意义的改进"（用户判据）。
