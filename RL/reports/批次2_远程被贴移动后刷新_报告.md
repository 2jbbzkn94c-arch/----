# 批次2 · 检视器 seed 7777 复合场景裁定与修复

## 0. 结论

**真缺口，不是采样窗口差。** 场景 `SIMCHK|n=20|u=医护兵(hero_06)#1|act=move+atk` 的两条 DIFF
（`医护兵有效攻 p=1>a=3` + `圣诞老人血量 p=20>a=18`）**同源**，根因是：

> 模拟里"远程被贴身 → 基础攻击压为 1"这个**派生量只在 `_evaluate` 刷新（搜索的父局面）**，
> `_apply` 执行"移动"之后**不刷新**，于是**同一招内**的伤害/治疗仍按**移动前**的攻击力算。

真实规则的顺序（`src/Battle.gd` `_do_move` → `_finish_move`）：单位落位后先
`_sync_ranged_adjacent()`（按新位置重算 `effective_atk = 基础攻击(被贴=1) + buff − 麻痹`），
**然后**才 `_trigger_on_move(u)`；本次攻击的伤害也在之后才用 `effective_atk()` 现算。

## 1. 两条 DIFF 的算术（为什么同一个根因）

`hero_06` 医护兵：基础攻击 3（远程）。快照时它**被贴身**（紧邻敌人）→ `effective_atk = 1`。

| 项 | 真实 | 修复前模拟 |
|---|---|---|
| 移动后解除被贴 → 参与本次攻击的攻击力 | 3（移动后重算） | 1（沿用移动前快照值） |
| 报告里的`有效攻` | 3 | 1 ← `有效攻 p=1>a=3` |
| 打在 `圣诞老人`（当时 21/24）上的伤害 | 3 → 21-3 = **18** | 1 → 21-1 = **20** ← `血量 p=20>a=18` |

两条 DIFF 是"同一个错值"的两个观测面（一个读派生字段，一个读它造成的掉血），
所以不是"采样时点差"：采样时点没问题，**是模拟算错了这一击**。

## 4. 改了什么（仅 `RL/ai/AI_Battle.gd`）

1. `_apply` 的移动分支：在 `_sim_on_move(...)` **之前**插入 `_sim_sync_pins(sim)`
   （对齐真实 `_finish_move` 的"先 `_sync_ranged_adjacent()` 再 `_trigger_on_move`"顺序；
   放在拾取/冲锋记账之后，所以金矿 +1 攻、大骑士冲锋加成不会被覆盖——大骑士是近战，刷新本就不碰它）。
2. `build_state` 末尾加一次 `_sim_sync_pins(s)`：把 `pin_buffs/pin_init` 的**反推时机钉在快照位置**。
   反推式是 `pin_buffs = 快照eatk − 当时基础值`，对数值本身是**恒等变换**；但若不在这里做，
   移动后第一次刷新会把"移动后的位置"当成快照位置，反推出错误的 buff。
