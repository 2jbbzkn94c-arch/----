### 各键的详细作用（下面 ①~⑩ 是目录式说明，仍然有效）

### ① 身价：打谁 / 保谁（静态，只看英雄身份，不含血量）

| 键 | 默认 | 作用 |
|---|---|---|
| `VALUE_SOLO_W` | 1.0 | × 这个英雄在角色列表里的「总评分」（`DataRegistry.hero_strength`） |
| `VALUE_RELATION_W` | 0.6 | ×（和队友的配合分 ＋ 对位克制分）——**配合与克制共用一个系数** |

- **公式**（`_unit_price()`，`src/BattleAI.gd:3363`）：
  `身价 v = solo × VALUE_SOLO_W × HERO_VALUE + (配合 + 克制) × VALUE_RELATION_W`
- **"配合 / 克制"的符号**（`DataRegistry.battle_unit_value_parts`）：**配合（`synergy`）≥ 0** —— 对每个队友求和；**克制（`counter`）是净值、可以为负** —— `Σ_敌人 [counter_bonus(我, 它) − counter_bonus(它, 我)]`，而 `counter_bonus()` 只返回 **2.0 或 0** ⇒ `克制 = 2 × (我克制的敌人数 − 克制我的敌人数)`，最坏 −6（3 个敌人都克我）。加权后每条净克制 = **±1.2 分**（`× 0.6`）。它是**静态对位关系**（只看双方阵容，不看本局战况）。
  （`HERO_VALUE` 是按英雄的可选覆盖，默认全 1.0；见下面"框架里的两个可选段"）
- **身价被用在哪**：① `_evaluate` 每个**存活**单位一项 —— 我方 `+v`、对面 `−v × 1.25`；② `_threat_forecast` 的"会被打掉" —— `− v × THREAT_DEAD_FOLD`。
- **单位一死，它那一项就不再进求和**（`if not u.alive: continue`）——所以"击杀"本身会带来一笔自动收益（对面 `+v × 1.25`）。

### ② 战术层：这一下划不划算（动态）

| 键 | 默认 | 作用 |
|---|---|---|
| `HP_VALUE_W` | 1.0 | ×（本回合打掉对面的血 − 自己掉的血）：**1 点血 = 1 分**。伤害收益全在这里（含反击、炸弹、灼烧等实际掉血） |

> **结构说明：身价是"加法项"，从不与伤害相乘**（用户 2026-09-18 问，见 §14#100）。整份评分 = **一堆加法项之和**：
> `身价（线性项）` + `HP_VALUE_W × 血量` + `frac² 集火` + `集火次数` + `击杀奖励` + `位置/威胁/规则B` …
> · **身价公式本身也是加权和**（`_unit_value`，3564-3566）：`单人评分 × VALUE_SOLO_W × HERO_VALUE + (配合 + 克制) × VALUE_RELATION_W`
>   —— 乘法只出现在**系数**上（`HERO_VALUE` 只乘"单人评分"那一支，**不是整体乘**）。
> · 进总分时仍是加法（3035-3040）：**己方 `+v`、对面 `−v × PLAYER_VALUE_MULT`**（对面再乘受控折减）。
> · 其它用到身价的地方**也全是加法**：威胁预判的"必死"罚（`− 身价 × THREAT_DEAD_FOLD`，3247）· 规则 A 净收益 `net = 身价 + 它下回合输出 − 我方掉血`（743）· 规则 C 落点分 `+100 + 身价`（781）。
> ⇒ **身价永不出现在"每点伤害值多少分"里**：伤害收益 = `HP_VALUE_W × 掉血`，**与打在谁身上无关**；身价只在**击杀那一刻**以阶跃兑现（那一项整项消失 ≈ +22~26）。
> 这正是"中间层没有身份差异"的根源（§14#70/#71）：**3+3 分摊给核心+杂兵 与 6 全压在核心身上，在身价 + 血量账上完全同分**，只有 `frac²` 能拉开。
> **历史**：原版"打谁"= 写死的 `eatk×1.6 + hp×1.0`（**也是加法**，但**含血量** ⇒ 与血量账重复计价、"血厚反而更值钱"倒挂），配合/克制是另一段写死的 `_synergy_value()`；
> 2026-09-15 统一成上面那条去血量的身价公式，同日晚些把战术层的"当下战力" `NUM_ATK_W×eatk + NUM_HP_W×hp`（**也是加法**）**整项删除** ⇒ **战术层现在只剩 `HP_VALUE_W` 一项，身价已完全不参与战术层**。
> ⚠️ 想改成"打核心更值钱"，只能动机制（伤害 × 身价比例 / 对高身价目标的伤害加成 / 规则 A 升级 / hero_XX 抬价）—— 前两者要改 `src/BattleAI.gd`，**须先经你同意**（§14#67）。
> ✅ **2026-09-18：第 (a) 条已实现**（用户批准走"默认关的机制键"这条路）—— 新键 **`VALUE_IMPORTANCE_POW`**
> （默认 **0 = 关闭 ⇒ 逐位不变**）把每点伤害的价值乘上 `clamp(身价(u)/基准, 0.5, 2.0)^p`，**两侧对称**
> （打对面核心更值钱 / 我方核心掉血更疼）。用法见 §一 末「✅ 规则 A/B/C 的键 + 身价乘法化」。

| ~~`FOCUS_TIMES_WEIGHT`~~ | ~~5.0~~ | **已于 2026-09-19 整项删除**（用户：「这个没用就删掉吧」）—— 语义与 `frac²` 重复 + 边际符号反（条件带 `u.alive`）+ 实测只归零 = **+1.02**（CI[−8.08,+10.11]，128 对）无影响 + 探针敏感度 **0.00** |

> 原本是**同一件事的两个尺子**（集火）：`FOCUS_FIRE` 是**伤害占比的凸函数**（0.3→2.7 · 0.5→7.5 · **打空 = frac 1.0 → +30**），
> `FOCUS_TIMES` 是**次数**（第 2、3 次各 +5）。⚠️ 它的条件里带 `u.alive`
> ⇒ **把目标打死的那一手会让这项消失**（性质与已删的"斩杀死线 +4"同类：边际符号是反的）—— 这已是它 2026-09-19 被删的第 ② 条依据。

>   `3+3 分摊`（各 0.15² → 合计 +1.35）与 `6 压一人`（0.3² → +2.7）在**身价 + 血量账上完全同分**，只有 `frac²` 能把它们分开。
>   ⇒ 这正是 `FOCUS_FIRE` 与 `KILL_BONUS` 的关键差别：后者与身价消失是**同一个阶跃、同一方向**（纯冗余，可设 0），前者是**连续凸函数**，身价里没有对应物。

- **键数账**：**引擎 19 个评分键 + 7 个规则/机制键 = 26**；`MOVE_ACCEPT_DAMAGE`（2/4/6/8）与 `VALUE_IMPORTANCE_POW`（1/2/3）是**两个需要扫值**的参数，其余都是开关或小权重。
- **`VALUE_IMPORTANCE_POW` 是什么（用户 2026-09-18 定：身价必须是乘法）**：用户原话「身价得是乘法吧？加法会被其他分数给稀释，所以出现了不合理的情况，身价一点都不重要。但我觉得身价非常重要」。
  **根因（比"稀释"更彻底）**：`_evaluate` 里身价项对**所有存活单位求和**，而同一局面下**每个候选动作面对的是同一个存活集合** ⇒ 这一项在候选之间**完全抵消、差值恒为 0**（实测旁证：把对面身价 `PLAYER_VALUE_MULT` 放大 16 倍，64 局里只 8 局改了出招；`VALUE_SOLO_W` 改 52 分一次出招都没改）。
  **落地**：作用在【战术层血量账】上、**两侧对称** —— 对面掉血 `+= HP_VALUE_W × 掉血 × w(u)`、我方掉血 `−= HP_VALUE_W × 掉血 × w(u)`，其中 `w(u) = clamp(身价(u)/基准, 0.5, 2.0)^p`、基准 = **本局面全部存活单位身价的均值**（自动算，不写死常数）。
  ⇒ p>0 时"打对面核心"每点伤害更值钱，**且"我方核心被打"也更疼（这一侧在改动前完全没有信号）**。
  **夹到 [0.5, 2.0] 的原因**：`_unit_value` 对召唤物（骷髅兵）恒为 0，不夹的话 p>0 会让"打召唤物"变成 0 分（它们仍会打死你）。
  ⚠️ **单靠乘法还不够**：实测 49 个英雄的单人评分只有 **15.20~21.90（1.44×）** ⇒ 乘法只放大到 1.44×；要真让身价"非常重要"，需要 `p ≥ 2~3` **或**配合按英雄抬价（`HERO_VALUE` / `hero_XX` 段 = 噩梦+ 通道）。
- **为什么默认关闭**：生产三档**逐位不变**（不注入权重时行为与改动前完全相同），规则只在噩梦/噩梦+ 生效；等你测完满意再改默认值（那一步才动生产）。
- **落地位置**：规则 A = `_cmp_state` + `_rule_a_gain`（并列裁决层）；规则 B = `_rule_b_score` + `_actions_for` 的排序段；规则 C = `Battle.gd::_sub_cell_by_rule_c` → `BattleAI.pick_sub_cell`。

## 三、三条硬规则（**已实现；默认关闭 ⇒ 生产逐位不变**）

> 用户 2026-09-15 定：**"其他的一些规则可以写死"** —— 下面三条是**硬裁决/硬约束**，**不是可调键**（不占训练维度）。
> 它们要解决的正是"权重做不到"的三件事：集火（83% 的决策被并列决定，软梯度会被淹没）、站位（只有拉力没有刹车）、替补（白站一回合）。
> ⚠️ **状态：设计稿，代码里一行都还没有**。完整设计 + 现状缺口见 `AI评分表_附注_实测与计划.md` §五。
> ⚠️ 按用户口径（§14#67）：生产三档不接受试验性改动 ⇒ 实现时以"**默认关闭（= 逐位不变）+ 噩梦档权重开启**"落地。

### 规则 A ·「合力可杀 + 净收益」（取代"能杀就强制集火"）

对应你的原则②「找核心、尽快集火、少分散伤害」。两步：

| 步 | 内容 |
|---|---|
| **门（能不能杀）** | `dmg_max(t) = Σ(我方本回合还没行动的单位各自能打出的最大伤害上界)`（含"要先移动"折算、射程、被贴身的远程只有 1 伤）→ 只有 `dmg_max(t) ≥ hp(t)` 才进"可杀候选" |
| **裁决（值不值得）** | `net(t) = 目标身价 + [它下回合本可造成的输出] − Σ_参战单位(本回合实际掉血：反击/炸弹/自伤) − [参战单位因此在下回合多挨的打]` → 只有 **net 为正、且优于替代方案**才升为优先，**绝不无条件强制** |

- **为什么不能"能杀就强制"**（复仇者 hero_23 算例：20 血 / 反击 ×2 = 8 且无限）：硬集火它 → 3 个单位各吃 8 = 24，`net = 20+8−24 = **+4**`；同样 3 人打**普通** 20 血单位（只有第一个吃 4）→ `net = **+24**` ⇒ 规则会**去打普通单位、放弃硬集火复仇者**。
- **放在哪**：**并列裁决层**（分数差 < ε 的动作之间按有序规则裁决）——不新增加分项 ⇒ 不占训练维度。
- **需要的键**：`FOCUS_KILL_RULE`（开关，默认 0 = 关闭）+ 可选 `FOCUS_NET_MARGIN` —— 见 §一 末「✅ 规则 A/B/C 的键」表；落地 = `_cmp_state` + `_rule_a_gain`。
- **上线后**：`FOCUS_FIRE_WEIGHT` / `FOCUS_TIMES_WEIGHT` 即可退场（它们想表达的正是这件事）。

### 规则 B ·「下回合站位约束」（够不到人时的走位）

> **尽量贴近敌人**；在能贴到的落点里，优先选 **下回合预期挨打 ≤ 可接受阈值** 的；若全都超阈值，就选"挨打最少"的。

| 子项 | 内容 | 现状 |
|---|---|---|
| **可接受伤害阈值** | 新增键 **`MOVE_ACCEPT_DAMAGE`**（**默认 0 = 关闭**，噩梦档 4，扫 2/4/6/8） | **缺**（这就是现在"保证不了停在敌方范围外/不撞进集火圈"的原因） |
| **逐格威胁的用法** | `_actions_for` **已经**逐格算了 `threat = _incoming_damage(sim, 格, 我方阵营)`，但现在**只当"主排序键相同时的次级比较"** → 升级成规则：`threat ≤ 阈值` 照常按"贴近"排；`> 阈值` 按**超出量强压**；全超标则选"最近 + 挨打最少" | 数据**已有**，用法**缺** |
| **路网躲避** | 落点让对方**路网距离 > 对方移动力 + 射程** → 显式加分（唯一能真正做到"够不着我"的手段） | **完全缺**（键 `EVADE_NETWORK_BONUS`，默认 0 = 关闭） |
| **我方下回合威胁** | 对称地算"我移动后下回合能威胁谁" | **缺**（键 `NEXT_TURN_THREAT_W`，默认 0 = 关闭） |
| **启用条件** | 只在"本回合够不到任何人"时启用，**与 `ENGAGE_PULL_PER_CELL` 协同**（拉力负责靠近、阈值负责挑落点） | — |

- ⚠️ **棋盘只有 5 列 × 7 行**，敌人包络半径（移动力 + 射程）常见 **3~6 格** ⇒ **"干净地站到所有人射程外"多数局面不存在** ⇒ **阈值才是主机制**，路网（卡墙后 / 死角 / 逼绕路）是补充。
- ⚠️ 现在下一回合挨的血只按 **0.12 分/点**（`THREAT_INCOMING_W`）计价，而本回合已掉的血按 **1.0 分/点** ⇒ **未来的挨打被低估约 8 倍**（挨 4 点只值 0.48 分，还不到 `ENGAGE_PULL` 一格 1.2 分的一半）⇒ 光靠权重"刹车"刹不住。

### 规则 C ·「替补落点要能直接参战」（独立、最便宜）

- **现状**：`src/Battle.gd::_place_enemy_sub()` 选**谁**用身价，选**哪**用 `_free_sub_cell_for()` —— 只有"优先本方墓碑格，其次出生区第一个空格"，**完全不看战斗**；虽然计划失效时会补一手，但从那格出发往往只能"走过去" ⇒ **白一回合**。
- **改法**：在合法落点（本方墓碑格 + 出生区空格）里按"**能否本回合打到人 → 打到谁最疼 → 离战场多近 → 下回合是否更安全**"打分选最优（同一套也可给我方自动落位用）。
- **需要的键**：`SUB_JOIN_RULE`（开关，默认 0 = 关闭）—— 见 §一 末「✅ 规则 A/B/C 的键」表；落地 = `Battle.gd::_sub_cell_by_rule_c` → `BattleAI.pick_sub_cell`。
- 对应你的原则④「已在交战时，替补落点应能直接加入战斗，而不是白浪费一回合」。
