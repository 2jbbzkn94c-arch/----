## 2. 「墓碑为什么自然落到新格」的实测证据链（含对照实验）

### 2.1 代码机制（先说清因果，再用实测坐实）

```
_do_attack → _apply_attack(血锁近战且 skips_lunge_anim → 全同步)
  ├─ target.take_damage(...) → hp=0 → Unit.die()      # alive=false；modulate.a 淡出 0.3s
  ├─ _trigger_on_attack → 目标已死 → _hero(u).on_attack_dead(target)   # ★ 同一帧
  │     └─ _pull_with_hook → Battle._pull_to → target.cell = 面前格   # ★ 0.3s 之前就搬好了
  └─ target.burst_fx(...)（击杀爆点）
... 约 0.3s 后 die() 的 tween 回调 emit died → Battle._on_unit_died(u)
  ├─ occupancy.erase(u.cell)      # src/Battle.gd:4287-4288 —— 用的是"当前的 u.cell" = 面前格
  └─ graves[u.cell] = {...}       # src/Battle.gd:4293    —— 碑也写在"当前的 u.cell" = 面前格
```

**结论：墓碑不需要单独搬。** 只要在 `_on_unit_died` 之前改了 `u.cell`，碑就写在新格。

- 所以按你第 3 条的要求：**不需要在血锁脚本里额外同步节点位置，更不需要动 `src/Unit.gd`**。

### 3.1 「炸弹为什么会和道具同格？」—— 不可能：代码是**双向排除**的（结论：S11 是防御性构造）

**（1）放炸弹的入口全部要求"该格没有道具/金矿"**

- `Battle.bomb_cell_ok(cell)`（`src/Battle.gd:3841-3843`）：
  `界内 and not occupancy and not obstacles and not bombs and **not buff_items**` —— 道具与金矿都记在 `buff_items`（金矿的值是 `"gold"`，见 1649 行 `place_gold`）。
- 三条落地路径都先过它：
  - 单机点选放雷：`_try_place_bomb`(3888) → `_apply_bomb_placement`(3917-3922) → `bomb_cell_ok(cell)` **且** `_hero(u).bomb_place_cells().has(cell)`；
  - 联机/回放：`_apply_bomb_cmd`(3905-3913) → 同一个 `_apply_bomb_placement`（注释写明"非法落点：忽略，不推进流程"）；
  - 单机敌方 AI 直放：`heroes/hero_35_炸弹人.gd:47-50` 先从 `bomb_place_cells()` 取格，而 `bomb_place_cells()`(25-32) 内部就是逐格 `battle.bomb_cell_ok(n)`。
- UI 橙色可放高亮（`_begin_bomb_place` 3859-3868）用的也是同一批格 → 连"点得到"都不可能。

**（2）放道具/金矿的入口全部要求"该格没有炸弹"**

| 生成路径 | 代码依据 | 是否排除炸弹 |
| --- | --- | --- |
| 圣诞老人回合开始放 2 个道具 `_place_buff_items` | `src/Battle.gd:1579-1584` `not occupancy and not obstacles and **not bombs** and not buff_items and not graves` | ✅ |
| 开局固定落点道具 `_spawn_opening_items` → `_opening_item_placeable` | `src/Battle.gd:1633-1635` 同上（含 `not bombs.has(c)`） | ✅ |
| 黄金矿工丢金矿 `hero_42_黄金矿工.gd:11-19` → `Battle.gold_cell_ok` | `src/Battle.gd:1643-1645` `not occupancy and not obstacles and **not bombs** and not buff_items and not graves` | ✅ |

**（3）写盘原语本身没有其它调用方**：`bombs[...]` 只在 `place_bomb`(3851) 写、`buff_items[...]` 只在 1590/1627/1649 写；
除了测试脚本（`tests/*`）和我的取证脚本，没有别的代码直接往这两个字典里塞东西。

**结论**：`bomb_cell_ok` 排除道具，三条道具/金矿生成路径排除炸弹 → **真机上"同格既有炸弹又有道具"不可达**。
所以：
- S11 只是"把口径固定下来"的**防御性构造**（我在场景里直接 `battle.bombs[FRONT]=true` + `battle.buff_items[FRONT]="atk"` 硬凑），
  报告里已标红为**不可达分支**，**不需要修**；
- 而 §3 表格里的 S4/S5/S6/S7/S10（落点是**纯炸弹格**或**纯道具格**）**都是真能自然出现的**：
  炸弹格/道具格都不是"阻挡格"（`_pull_to` 的落点搜索只跳过 `occupancy/obstacles/graves`），
  所以血锁完全可以把目标拉进一个"有人放过的雷"或"地上躺着的道具"上——那才是这次改动要处理的真实情形。

1. 开一局（任何模式），把你的**血锁**摆在**同一条六边形直线**上、距离某个**血很少的敌人 2~3 格**
