## ⚠️ 已踩的陷阱

1. **5 个 spec 是同一批对局**：不加 `-FixedDecks` 时阵容按种子随机抽 ⇒ 多 spec 跑出来逐位相同。**改"单 spec + 多种子"**。
2. `FATAL: RUN LOCK … exists`：杀批留下陈旧锁 ⇒ 校验锁内 pid 不存在再删。
3. `FATAL: only 9 of 10 worker(s) reported`：病态格跑 30+ 分钟 ⇒ 自己从 `w*/measure.csv` 聚合（`agg_multi.py`）。
4. `FATAL: LEAGUE ARM MISMATCH`：多臂 beam 不同 ⇒ 对手身份被判不同 ⇒ **beam 扫描只能一臂一 run**。
5. **`opp=base` ≠ 难度3**：那是 `AI_Battle_原版.gd` + difficulty=2 = 困难口径。要难度3 必须走 `league.checkpoint`。
6. **缺格的批会被拒合并** ⇒ 每格 `-TimeoutSec 900` 兜底 + 自聚合。
7. **引擎在跑批期间被改 ⇒ 对照失效**（2026-10-02 实测）：隔壁 19:03 改了 `src/BattleAI.gd`（T121），

## 深度这一路（`REPLY_PEEK` · 批次6）

- **机制**：两阶段搜索收尾处，把前 K 个完态各克隆一份，**让对面按贪心打一个回合**（`_reply_turn_score()`），
  再用**完整 `_evaluate()`** 重排。对手的招由**阵营中立**的 `_reply_step_value()` 挑（只认"谁掉了多少血、掉的是谁"）
  —— **绝不能用 `_evaluate`**（它阵营不对称 ⇒ 等于让对手按我们的价值观走棋，当年"真推演"的根因）。
- **有意不吃 `TIME_BUDGET_MS` 的余额**（只受 `abort_requested`），否则最难的回合反而瞥不到 ⇒ 静默失效。
- **键名不叫 `REPLY_TOPK`**：那个名字 2026-09-20 已判死（rp4 −0.45 / rp8 +1.74），本键**同名不同机制**（对手模型/重排公式/挂点三处都换）。
- **读数**：`p8` +1.53 · `p16` +0.54 · 剂量 −0.99 ⇒ **全跨 0**；机制活跃度实测：平均重排 14.2 个末态/回合、
  **73.2% 的回合改了选择**、耗时占搜索 ~1.7% ⇒ **在搅动决策、不在变强**。
- ⇒ **结论：「我方一回合 + 对手一回合」这一层深度在本引擎上不兑现**（与旧 `REPLY_TOPK` 两次独立实现一致）。
  **根因**：评估器分辨率太粗（83% 的局面分差 < 0.5）⇒ 搜得再深只是重排噪声。**想分辨 +1.5 需 N≈550 配对**。

### 陷阱 12：**`-TimeoutSec` 不只是"单局上限"，它决定整批的全局死线** —— 给 900 就只有 35 分钟

`RlTrain.ps1` 的 `Invoke-ParallelCells`（约 2531-2547 行）：

```powershell
$deadline = $t0.AddSeconds(($TimeoutSec * 2) + 300)   # ← 整批的墙上时钟预算
...
Write-Host ('[par] !! GLOBAL DEADLINE HIT after ... (' + $TimeoutSec + 's x2 + 300s); stopping ...')
foreach ($j in $running) { Stop-Job -Job $j }
...
throw ('Invoke-ParallelCells: only ' + $results.Count + ' of ' + $jobs.Count + ' worker(s) reported a result; refusing to merge')
```

**本次实测**：三个批（`nm1_v3` / `nm1_v4` / `nm1_nx` 第一次）都用了 `-TimeoutSec 900` ⇒ 全局预算
**900×2+300 = 2100 s = 35 分钟**，而每批要 1.5~3.5 小时 ⇒ **三次全部死在起跑后 33~35 分钟**，
每个 worker 各留下 ~19-24 局（`w*/measure.csv` 都还在，只是父进程拒绝合并）。
⚠️ 我一开始把它误判成"探针把 worker 杀了"（时间上确实撞上了 v3 那一次），**是错的** ——
v4 与 nx 都没有探针介入，照样在同一时长上死 ⇒ **判据是"时长"、不是"有没有人碰它"**。

**怎么算够**：全局预算 = `TimeoutSec × 2 + 300` 秒。10 个 worker、单局 ~97 s ⇒ 每局约 6.2 局/分钟
（1280 局 ≈ 3.5 h）⇒ 要跑 N 局就取 `TimeoutSec ≥ (N/6.2×60 − 300)/2`。
本次 1280 局取 **7200**（全局 4.08 h，单局上限 2 h 只是保险丝）。
**另一个坑**：`[par] !! GLOBAL DEADLINE HIT` 这行**会被 `Select-String 'TOTAL wall|FATAL|ERROR'` 滤掉**
⇒ 只剩一个 FATAL，看起来像"worker 全崩了"。**过滤条件里一定要带 `GLOBAL DEADLINE` / `accounting` / `all workers done`。**
