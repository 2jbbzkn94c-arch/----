## 1. 机制（复用既有注入机制，没有新造一套）

| 位置 | 内容 |
|---|---|
| `AI_Battle.HERO_VALUE_DEFAULT` | **内置默认表**（49 英雄，按定位分档），见 §2 |
| `AI_Battle.w_hero_value` | 注入表（`hero_id -> float`），空 = 用内置表 |
| `AI_Battle.set_weights()` | 新增识别 `"HERO_VALUE": { "hero_22": 1.35, ... }` 段（与 12 个通用键同文件） |
| `AI_Battle.set_hero_weights()` | 同一段也走既有英雄特化入口（`{"HERO_VALUE": {...}}`），与 `{"hero_42": {"GOLD_TAKE_VALUE": 40}}` 结构同族 |
| `AI_Battle._hero_value(id)` | 注入优先 → 内置默认表 → 1.0 |
| `AI_Battle._unit_value()` | `base = (eatk*1.6 + hp*1.0) * _hero_value(hero_id)`；后续词条加成（远程/嘲讽/疾行/后勤/圣盾）与状态折减**保持不变**；骷髅兵仍恒 0 |

**一个系数同时管两件事**（注释里写清了）：`_evaluate` 里 `score += v(己方) / score -= v(敌方)*1.25`，
所以敌方英雄系数越高 → 打死它抹掉的负分越大 → **优先集火核心**；
己方英雄系数越高 → 活着贡献越大 → **优先保护核心**（另一处 `_incoming_damage` 的威胁扣分同理）。
**完全 data-driven、可注入、可回退**：删掉 JSON 里的 `HERO_VALUE` 段 → 回内置表；把值全填 1.0 → 行为与改动前一致。

## 4. 用户以后怎么调这些系数

权重文件：`RL/weights/噩梦.json`（噩梦档敌方 AI 每局开打时读一次；改完重开一局即生效）。
通用键（12 个）用法不变，**新增英雄段**：

```json
"HERO_VALUE": { "hero_22": 1.35, "hero_06": 1.30, "hero_13": 0.90, "hero_40": 0.90 }
```

- 键 = 英雄 id（`hero_01`~`hero_49`），值 = 核心价值系数；**没写的英雄 = 内置默认表的值**；
- **整段删掉** → 全部回内置默认表；把某个英雄写成 `1.0` → 该英雄"与改动前完全一样"；
- 建议范围 **0.8 ~ 1.5**：`>1` = "这是队伍核心，优先打死它、也优先保它"；`<1` = "死了也不太亏 / 打了会被反噬"；
- 系数**同时**作用于"打它的优先级"和"保它的意愿"（设计如此）；只想要一个方向时，可把值放在 1.0 附近微调。
