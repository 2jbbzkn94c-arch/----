# 从 CombatSolver（杀戮尖塔2 战斗求解器 mod）能借鉴什么

> 来源：[Torch1230/CombatSolver](https://github.com/Torch1230/CombatSolver)（MIT，README 于 2026-09-18 读取，版本 0.40.2）。
> 用户 2026-09-18 提问：「这是别人做的杀戮尖塔2的mod，ai帮打牌，很强。从这里面你能得到什么应用到战旗里的灵感吗？说实话，我觉得对困难模式60%胜率我并不满意。因为我自己和困难打，基本能100%胜率」（§14#104）。

## 一、它到底强在哪（读 README 得到的事实）

| 它的做法 | 原话/事实 |
|---|---|
| **搜索的是"整场战斗的路线"** | 「跨回合搜索：继续预测抽牌、洗牌、敌人行动、持续状态和后续资源，而不是只计算眼前一回合」 |
| **目标函数是【结局量】+【字典序】** | 「最终路线**依次比较：生存、确认胜利、整场战损、药水消耗、主动卖血和敌方剩余状态**」⇒ 先活、先确认能赢，再比整场掉血，再比资源 —— **不是特征加权和** |
| **精确模拟整场战斗** | 主线程抓一次根状态，后台在**独立模拟分支**上推进卡牌/牌堆/RNG/怪物 AI/药水/遗物/跨回合效果；不动真实 RNG |
| **预算很大** | 预设：**60s/60k 节点 → 120s/120k（默认）→ 180s/250k → 300s/500k**；节点+时间+内存三重预算 |
| **并行搜索** | 默认 4 路（4+ 逻辑核），可 2–16 路；NoGC 区域（16GB 请求预算）专治搜索期 GC 抖动 |
| **状态合并 / 循环检测 / 路线复用** | 明确写了「循环检测、状态合并和预算终止仍会限制实际搜索范围」；「实机状态与预测一致时**直接沿用既有路线**，只有状态发生实际变化时才重新搜索」 |
| **诚实边界** | 「遇到尚未支持的新版本或第三方战斗语义时，求解器会**明确停止在不支持边界**，不会把未完成模拟误报为胜利」 |
| **模拟器验证闭环** | `docs/COMBAT_HOOK_COVERAGE.md` + `docs/ADAPTATION_VERIFICATION.md`（逐条机制 Pass/Fail + runId） |
| 引擎 | Beam Search（**它自己也不声称全局最优**：「展示当前预算内找到的最佳路线，不承诺数学意义上的全局最优解」） |

**一句话**：它强，是因为它把「打这一手」变成了**在精确模拟器上搜到"整场战斗的结局"**，并用**结局量的字典序**排序；不是因为它有更好的评分权重。

## 二、对照我们的现状（差距在哪）

| 维度 | CombatSolver | 我们（战旗 `src/BattleAI.gd`） | 证据 |
|---|---|---|---|
| 目标函数 | **结局量 + 字典序**（生存 > 确认胜利 > 整场战损 > …） | **19 个特征的手调加权和** ⇒ 中间层几乎无信息：**83% 的决策分数并列（margin 0.000）** | probe 实测；§14#70/#71 |
| 视野 | **跨回合**（预测抽牌/洗牌/敌方行动/持续状态） | **只搜自己这一回合**（`search()` 只扩本方单位）；对玩家回合用**静态启发式** `_threat_forecast` | `src/BattleAI.gd:641-680 / 3280-3299` |
| 算力 | **60–300 s / 一手**，4–16 路并行 | **0.5–2.4 s / 一手**，单线程 | 实测 `search_ms_max=2438`；每回合 2.3–5.4 s |
| 终局感知 | **"确认胜利"是第一优先** | ⚠️ **`_evaluate` 里没有任何终局项**；而噩梦档把 `KILL_BONUS` 与 `SELF_DEATH_W` **都设成了 0** ⇒ **噩梦现在完全没有"死 3 个就输/对方死 3 个就赢"的意识** | `src/BattleAI.gd` 注释自述："`_evaluate` 没有任何终局项"；`噩梦.json` 现状 |
| 状态合并 / 循环检测 | 有 | 无（只有 beam + 时间预算） | `search()` |
| 每步增量复用 | 路线复用 | 无（每回合重搜，虽然本回合内是一次性出整条方案） | — |

⚠️ **最有冲击力的一条**：人打这游戏是围绕「死 3 个判负」下的，而**我们的噩梦档恰好把唯一两个与"死亡/击杀"有关的键都删成 0**（`KILL_BONUS` 0、`SELF_DEATH_W` 0）。**这解释了为什么你 100% 打得过困难档、也解释了为什么 26 个键怎么调都只有 ±5 分**：AI 根本没有"我要输了/我要赢了"的概念，它只在中间层比"这一下划不划算"。

## 三、能借鉴的五条（按性价比排序）

### ① 先给引擎加"终局/胜负条件"意识（最便宜、最可能直接解决"人 100% 打得过"）
- **字典序而非加权和**：`生存 → 确认能赢 → 战损`。落地形式（默认关的键，生产逐位不变）：
  · **我方阵亡数 ≥2 时**，"再死一个"给巨大惩罚（阈值型，而不是现在那条线性 −20 身价）；
  · **对方阵亡数 ≥2 时**，"本回合能不能收掉最后一个"给巨大奖励；
  · 这两条正好是**人类玩家最擅长、AI 现在完全没有**的东西。
- 代价：`_evaluate` 里加一小段（<30 行）+ 一个新键；可先用现有 harness 跨队验证。

### ② 把"中间层特征加权和"升级成"结局评价"（真正的强度跃迁）
- 现在的流程：`beam 展开 → 每个中间态都用加权和打分`。
- 借鉴后的流程：**beam 只做粗筛**，对**候选末尾的前 K 个终局态**（K≈8–16）做「**对手最优反击一层**」的精确推演，然后用**结局量**（我方/对方剩余总血、双方阵亡数、是否触发判负）按**字典序**比较。
- 这一步同时补上 Doubao 说的 Depth=2 和 CombatSolver 的"结局量排序"，而且是**确定性完全信息** ⇒ 不需要采样、不需要训练。
- 代价：中等代码量 + K 倍算力（K 可控）；但**不改变"生产三档"**（默认关）。

### ③ 算力：并行 + 在玩家回合期间预计算
- CombatSolver 一手牌花 60–300 s，是因为它在后台线程算、用 4–16 路并行、还有 NoGC 区域抗抖动。
- 我们的 AI 是**真·实时**（0.5–2.4 s/手）。但战棋有一个**免费的预算窗口**：**玩家思考的那几十秒**。
- 落地：① 敌人回合开始时（或在玩家回合空档）**后台预计算**下一手，玩家一结束回合立刻出招；② 用 Godot 线程把 beam 展开并行化（我们离线跑对局时已经有 12 进程并行的经验）。
- 这直接对应你的**要求②（压缩每回合耗时）**：不是单纯变快，而是**把省下的时间换成搜索深度**。

### ④ 难度阶梯可能根本是假的（先测，再改）
- 我们的四档只差 `BEAM` 50/100/200 + `JITTER` ±8/±1.5/0 + 权重；而已测：**同一套引擎把 beam 从 100 提到 1200，胜率毫无变化**（50.0/56.2/53.6/50.0，N=24–32）⇒ **"算力"不是我们现在的瓶颈，"评分"才是**。
- 所以**第一件该做的事是测「简单 vs 困难」的胜率**：如果 ≈50%，那么"难度"目前只是噪声大小不同（jitter），而不是强弱不同 —— 这对游戏体验是硬伤，也解释了为什么你打哪个档都轻松。
- 落地：1 个 spec、2 条臂、镜像、8 队即可（≈20 分钟）。

### ⑤ 工程纪律：两条我们已经做得不错、要坚持的
- **模拟器验证闭环**：他们逐条机制 Pass/Fail + runId；我们有 `对拍`/`技能对拍`/`逐位不变验证`（今天刚用 8/8 行逐字节证明新键在默认值下不改行为）。
- **不支持就停在边界**：他们明确拒绝"把未完成模拟误报为胜利"；我们该把"引擎不知道的情况"也显式标出来（而不是让 `_evaluate` 用一个瞎猜的加权和糊过去）。

## 四、关于"60% 胜率不满意"这件事（我的判断）

1. **你的不满是对的，但问题不在 60% 这个数字，而在我们测的东西**：判据是「候选 vs **同队伍困难档**」，而困难档 = **同一套引擎 + 同一 beam**，只有权重不同 ⇒ 这是个**近乎对称的比赛**，数学上就不可能赢很多。**60% 不是"AI 变强了 60%"，而是"两个几乎相同的引擎互打的噪声上限"。**
2. **你 100% 打得过困难档，才是真正有价值的证据**：它说明**困难档有可被人类稳定利用的漏洞**，而这些漏洞**几乎肯定不是"某个权重差 5 分"**，而是**结构性的**：没有终局意识（①）、只看一回合（②）、把"这一下划不划算"当成全部（中间层无信息）。
3. **新的验收口径建议**（需要你拍板）：
   - **主判据**：`噩梦(新机制) vs 困难(现状)` 的**镜像胜率必须显著 > 50%，目标 65%+**（而不是 0.5357 这种噪声级）；
   - **反向判据**：`噩梦 vs 噩梦` = 50%（对称性自检，我们已有 p0 = 0.5000 的现成证明）；
   - **绝对判据**：**你能不能在噩梦档下不再 100% 赢** —— 这是唯一真正有意义的"变强"标准；
   - 留出集 96 局的 Wilson 下界 > 0.5 只当"统计显著"的门槛，不当"够强"的门槛。
4. **权重路线该收摊了**：9 批 ≈4700 局 + 今天的乘法化负结果（§14#103），已经足够说明**继续扫 26 个键的收益上限在 ±5 分/局**。剩下的算力应该投到 ①②③，以及 §14#102 的卡位/持久目标。

## 五、建议的下一步（三件，按顺序）

1. **终局项 + 字典序**（①）：默认关的新键，跨队测；预期直接改善"人类能利用的送人头/不收割"。
2. **简单 vs 困难的胜率测试**（④）：验证难度阶梯是否真的存在（≈20 分钟，和 1 并行）。
3. **结局评价（对手反击一层）原型**（②）：先只在"最后 K 个终局态"上做，控制算力；用 1 测得的"是否真的有强弱差"来判断值不值得扩到全局。
