## 1. P0 根因与改法

**根因（按行核对）**：`GameState.dual_control` 一个标志管两件不相干的事——
- `src/Battle.gd:1834-1848`：`dual_control=true` → 敌方轮**不跑生产 AI**（直接 return）；`false` 才走底部 `_run_enemy_turn.call_deferred()`，生产 AI 自开后台线程；
- `src/Battle.gd:1922-1923`：`_is_manual_sub_faction()` 在 true 时对双方都成立 → 阵亡走手动面板，生产替补链被跳过。

我上一版为了拿到"生产替补链"而把 `dual_control` 置 false（`_sync_dual_control()`），**连带打开了生产 AI** → 同一回合两个驱动者 → 两个 `_run_enemy_turn` 协程并行，后一个把 `_ai_thread` 置 null，前一个随后 `wait_to_finish()` 撞 null（`Battle.gd:5047`）。

**改法 1（撤销错误做法）**：`_sync_dual_control()` 现在**恒置 true**，并写清了上面这段因果，避免以后有人再拿它去换替补行为。

**改法 2（替补改用生产口径，不发明优先级）**：新增 `_ai_drive_sub(side)`——
- **选谁**：`_battle._best_enemy_sub_idx()`（生产 `_place_enemy_sub` 用的同一个"此刻最合"评分，`src/Battle.gd:4388`）；
- **怎么落位**：`_auto_sub_on_timeout()` 走的同一条 API（`_on_sub_pick(hero)` → `_auto_sub_cell(fn)` → `_try_place_sub(cell)`，`src/Battle.gd:4508-4526`）；
- 唯一差别：面板/超时路径挑 `roster[0]`，这里挑生产最优下标。落点、墓碑清理、光环、登场技全走 Battle 自己的代码。

**改法 3（硬保护，防再犯）**：新增 `_production_ai_busy()`，命中任一即**退让**并让 `_need_ai_turn()` 返回 false：
1. `_battle._enemy_plan_running`（Battle 回放期）
2. `_battle._ai_thread` 已启动（Battle 后台搜索在跑）
3. `_battle.state == ENEMY_TURN`（只有 dual_control=false 才会出现）

另有 `_ai_driven_by_us(side)` 供替补路径复用同一判断。

## 2. 怎么验证"不再双驱动"（方法，不只是结论）

判据是**日志互斥**，不是主观判断：

- 检视器驱动某一边时必然打印 `[检视器] 第 N 回合·我方/敌方：AI=… 计划 M 招`，随后是该回合的 `SIMCHK|` 逐招行；
- 生产 AI 自己跑时必然打印 `[检视器] 档位=…` **不出现**，而会出现 Battle 侧 `_run_enemy_turn` 的行为（且 `dual_control=false` 会有 `[检视器] 强制 dual_control=true` 之外的路径）；
- 实测三次运行：**没有一次**同时出现"生产 AI 决策"与检视器计划驱动；`dual_control` 保持 true 时 Battle 不再自动跑敌方回合。

另外用 `wait_to_finish` 计数做硬断言：三次运行均为 **0**（之前的崩溃签名就是这条）。

### 3.3 已知差异（保留，不为它发明逻辑）
我方 = RL 时，我方替补在**生产**里恒为手动分支（`fn == _my_faction()`），我在这里用 `_best_enemy_sub_idx()` 对玩家阵容打分意义有限（那个函数是按"敌方需求"写的：缺嘲讽补坦克、多负伤补光环等）。所以：
- **敌方 = AI 时**：替补口径与困难档一致（本报告已给证据）；
- **我方 = AI 时**：选人用的是敌方口径的评分（能用，但不等价于"我方最优"）；落位仍走生产 API。
按要求**保持为已知差异**，未自行发明我方优先级。

### 3.4 DIFF 分类（未放宽任何判定）
14 条按性质分三类，全部如实上报、无 try/catch、墓碑/地形字段一个没排除：
1. `墓碑@x,y p=有>a=无`（成对反向）= **采样时机差**：真实 `Unit.die()` 先 0.3s 淡出才 `died` 立碑，模拟是立即立碑；
2. `有效攻/有效移 p=…>a=…` = **比对口径差**：真实 `effective_atk/move` 依赖实时 `ranged_adjacent`/状态，SimUnit 是建快照时的静态字段；
3. `障碍耐久 p=3>a=2`、`血量 p=22>a=20` 等集中在**敌方=原版困难档**的招上 = **真缺口**：原版 AI 缺候选版那批 `【RL 修正】`（技能波及障碍、冰冻减速、阵亡统一结算…）。同一局面下候选 AI 全 MATCH 可作对照。

## 4. 默认进选人界面 + 拦截「返回选人」（已实现；端到端待真人点选验证）

- **默认值**：手动游玩（F6）默认 `_handpick=true` → 不填 `placement` → `Battle._begin_deployment()` 选人界面。`--selftest` 一律固定 3v3；新增 `--fixed3v3` 显式走固定沙箱。
- **勾选框立即生效**：`_hp_check` 默认勾上；切换即 `_rebuild_sandbox()`（不再需要重开场景）。
- **拦截**：`_hook_hud_back_button()` 每次 `_setup()` 后重新挂接；用 `pressed.get_connections()` 枚举出 callable 名为 `_on_back_to_menu` 的连接并断开，再连 `_on_back_to_select`（= 重建沙箱 + 回到选人界面，不换场景）。按钮用文案 `返回选人` 递归查找，不依赖 `src/HUD.gd` 的私有成员名。
- **就地重建**：`_rebuild_sandbox()` 顺序为 ① `_run_gen+=1` 作废旧驱动协程 → ② `_stop_search_thread()` 回收线程 → ③ `_reset_instance_state()` → ④ `queue_free` 旧 Battle 并等它离开场景树 → ⑤ 重置 GameState（`match_over/round_number/active_side/decks/placement`）→ ⑥ `_setup()` → ⑦ 重新挂接返回按钮 → ⑧ 重启 `_run()`。旧循环在循环头与各 await 后比对代际号，不一致即 return，避免两套驱动并行。
- **降级分支**：找不到 HUD / 按钮 / 断不开连接时只 `push_warning` 说明"仍会跳主菜单"，不崩、不改游戏节点。**本次运行未触发降级**（`hp_panecheck.log`：断开 1 条原连接）。
- **未验部分（如实说明）**：真人点选 3v3 落位、以及"点返回选人来回 3 次"这两项需要手动 F6 操作，我无法在无头下完成；`--panecheck` 只证明到"按钮已成功拦截+面板结构正确"。请手动跑一次确认。

## 5. 手动验法（点哪里、看什么）

1. 编辑器打开 `RL/harness/自由部署_模拟检视.tscn` → F6：**应当直接进入选人部署界面**；状态行显示「手选部署中：请双方各选 3 人并落位」。
2. 双方各点选 3 人并落位 → 进入对局，逐招出现 `SIMCHK|` 行。
3. 面板「敌方控制」切到 `RL候选AI` 或 `原版困难档` → 该方回合由 AI 出手；状态行显示「AI 思考中…（…已 X ms）」，**期间仍可点「折」/切档**（搜索在后台线程）。
4. 点游戏内「返回选人」→ 应当**就地回到检视器自己的选人界面**（日志出现「[检视器] 返回选人：已重建沙箱，回到选人界面」），**不跳主菜单**。
5. 面板取消勾选「走部署选人」→ 立即重建为固定 3v3；再勾上 → 回到选人界面。
6. 来回切换数次：不应出现 "Thread must be disposed"、不应卡死。
