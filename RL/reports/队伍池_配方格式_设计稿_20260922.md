## 0. 一句话

有配方的档（困难/噩梦走 `strong`）：每场**随机抽 1 个类型** ⇒ 得到"首发槽位的候选池"（后台）+ 替补策略（预设 / **动态**）；部署时**按槽位**从该槽位的**全部候选**里按分数 + 抖动挑人；**没预设替补的类型，替补席留空**，等战斗里真的需要补位时，再从**英雄池**按**局面**挑一个最合适的（能斩杀 ⇒ 上够伤害的；我方将崩 ⇒ 上梅林这种救人牌）。候选池与英雄池**都不进卡组**。

## 1. 文件格式（v4）

```jsonc
"strong": [
  ["hero_11", "hero_07", "hero_21"],                 // 旧格式：固定队伍（3，或 5~8 = 首发+替补）

  {                                                   // 新格式：类型（配方）
    "id": "T1",
    "note": "近战输出 + 远程输出 + 嘲讽（嘲讽按对面已首发挑，带随机）",
    "slots": [                                        // 首发 3 槽，按顺序填
      { "pool": ["hero_01","hero_03",...] },          // 候选全集（不进卡组）
      { "pool": ["hero_06",...] },
      { "pool": ["hero_11","hero_25","hero_44",...] }
    ],
    "bench": ["hero_08","hero_45","hero_38"],         // 可选：预设替补
    // bench 不写 ⇒ 该类型走"动态替补"（见 §2），开场只有 3 个首发
    "w": 1.0
  }
]
```

| 字段 | 含义 |
|---|---|
| `slots[].pool` | 该首发槽的**候选全集**（生成端把中文/别名/特性/排除表展开成 hero_id）|
| `slots[].fixed` | 可选：锁定单个英雄 |
| `bench` | 可选：**预设替补**（类型 3/4/5 写了）；**不写 ⇒ 动态替补** |
| `w` | 类型权重（默认等权）|

## 2. 时点（v4 的核心修订）

```
[A] 卡组组建（部署之前）
      随机抽 1 个类型 ⇒ 写 GameState.enemy_recipe（槽位候选池 + 预设替补 或 "动态替补"标记）
      · 有预设替补 ⇒ enemy_deck 初始 = 预设替补名单（部署界面能看到）
      · 动态替补   ⇒ enemy_deck 初始 = **空**（开场只有 3 首发，替补席留空）

[B] 开局部署（随机先手，交替各选 3 —— 做法乙：按槽位填人）
      敌方第 i 次选人：候选 = 配方第 i 槽的候选池 − 已上阵
        score = 既有打分(含对玩家已首发净克制) + randf() × PICK_JITTER
        取最高（并列随机）；锁定槽直接上；<替补>标签英雄不主动首发（既有口径）

[C] 战斗 · 需要替补时（★ v4 新增：动态替补）
      触发点 = 阵亡后补位：src/Battle.gd::_place_enemy_sub()
      · 有预设替补 ⇒ 走现有逻辑（_best_enemy_sub_idx() 从 enemy_roster 里挑）
      · 动态替补   ⇒ 候选 = **英雄池**（排除本局已上阵/已阵亡/已在场的），
                     按 §3 的**局面判据**挑 1 个（含落点一起评估），再按既有落位流程上场
```

> 为什么替补必须等到那一刻：你要的两条判据（"能斩杀""我方将崩"）**只有在当时的盘面上才算得出来** —— 开场时既看不到对面站位，也不知道谁会残血。

## 3. 动态替补怎么挑（v4 新增，判据按优先级）

候选 = **英雄池**（口径见 §7-1）× **合法落点**（既有 `_sub_legal_cells_for_ai()`）配对评估，取最好的一对：

| 优先级 | 判据 | 怎么算 | 对应你的例子 |
|---|---|---|---|
| **1. 能斩杀** | 存在"这一手就能打死"的敌方目标 | 用既有 `dmg_max ≥ 目标当前 HP` 门（AI 侧斩杀判据同源）：若某候选落在某格后能击杀，**取"伤害最高/最稳"的那个**（而不是按评分）| 「可以斩杀的时候，一个够伤害的高攻比其他替补都合适」|
| **2. 救人 / 止血** | 我方有单位"下回合必死"或整体要崩 | 用既有威胁量 `_incoming_total_on()` ≥ 该单位 HP 判"必死"；命中 ⇒ 优先能救的：**梅林 hero_36**（回复最低血队友 8 点 + 换位）、治疗类（`MECH_TAGS["治疗"]` = 医护兵06/德鲁伊08/风语者43/梅林36/圣诞老人02）、能挡的嘲讽（把火力吸走）| 「我方有个英雄下回合必死、我准备要输了 ⇒ 梅林也是个很好的选择」|
| **3. 补缺口** | 阵容结构性缺口 | 既有 `_best_enemy_sub_idx()` 的三条：缺嘲讽 ⇒ 补坦克；多人负伤 ⇒ 补光环/治疗；输出偏少 ⇒ 补远程 | （既有逻辑，保留）|
| **4. 兜底** | 以上都不成立 | 既有身价/协同评分 + **随机抖动**（同一个 `PICK_JITTER` 口径）⇒ 不会每次都同一套 | 你要的"别太机械" |

附带两条实现要点：

- **落点要一起算**：判据 1/2 都依赖"落在哪"（打不打得到、救不救得着）⇒ 用（候选 × 落点）配对打分，落点仍受既有规则约束（`SUB_JOIN_RULE` 规则 C：同批合法落点里挑"能立刻参战"的）。
- **上阵后本回合就要能用**：既有 `_plan_enemy_late_sub(eu)` 已经负责"敌方回合中途落位的补一手" ✓ 不动。
- **`<替补>` 标签英雄**：动态池里**允许**（梅林/猎颅者正是 `<替补>` 标签，技能只在替补登场触发 ⇒ 天生适合这条路）。

## 4. 随机性（治"我一上负面对面就掏负墟"）

```
score_final(候选) = 既有打分 + randf() × PICK_JITTER
```
- `PICK_JITTER` 默认 **2.0** = 一次克制分的权重（`counter_bonus` 每次 2.0）⇒ 约"七成按分数、三成随缘"；写 0 = 恢复精准克制。
- 并列/近似并列 ⇒ 随机，不取第一个。
- 常数放池子 `meta`（`"pick_jitter": 2.0`）⇒ 你玩着不对自己就能调，不改代码。
- 门控：**只在配方档生效**（strong = 困难/噩梦）；简单/普通走 weak/mid 固定队伍 ⇒ 行为不变。
- 动态替补的判据 1/2 **不吃抖动**（那是"明确的战术机会"），只有判据 4 的兜底吃抖动。

## 8. 还需你点头的 4 件

1. **英雄池的范围**：动态替补从"**全部英雄**"里选，还是从"**池子文件里出现过的英雄**（8 个类型候选的并集）"里选？后者更可控（不会突然冒出一个你没设计的英雄）。
2. **判据 1（斩杀）的尺度**：只算"**这一手就能杀**"（落点 + 射程 + 伤害 ≥ HP），还是也算"下回合能杀"？
3. **判据 2（救人）的"必死"口径**：用"挨打合计 ≥ 当前 HP"（`_incoming_total_on()`，与 AI 评分同源）吗？
4. **`PICK_JITTER` 默认 2.0** 可以吗？（嫌太会克制就调 3~4；嫌太傻就调 1）
