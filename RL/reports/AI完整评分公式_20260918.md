# AI 行为的完整评分公式（2026-09-18 · 逐项抄自 `src/BattleAI.gd::_evaluate`）

> 用户 2026-09-18：「你给我列的键里，我没有看到关于身价和身价自动扣除的地方。我让你列键的时候，我需要你先把总的影响AI行为的评分公式写出来，再解释公式里细分项的意义，不要漏」（§14#110）
> **为什么上一份键清单里看不到身价**：身价是**公式里的一项**，不是一个键 —— 它的"自动扣除"更是**求和范围的改变**（单位死后不再进求和），根本没有键可控。所以列键永远列不出它。本文按代码顺序把 `_evaluate(sim)` 的**全部**项抄下来。

## 一、主评分函数 `_evaluate(sim)` —— 完整公式（按代码顺序）

```
score = 0

①  score -= _obstacle_detour(sim)                                # 障碍绕路代价（按路网真实绕路）

②  [统计] 我方阵亡计数：my_dead_before / my_dead_now
      · 骷髅兵（summon_skeleton）不计
      · `_was_doomed(u)`（所有可达格都会死）不计
      · hp0 > 0 才算"本回合新阵亡"

③  逐单位【★★ 身价层 = 打谁/保谁 ★★】          ← 你要找的那一项在这里
      v = _unit_value(sim, u)
        = solo(u) × VALUE_SOLO_W × HERO_VALUE(u)
        + ( synergy(u) + counter(u) ) × VALUE_RELATION_W
      若 u 是**对面**（玩家方）：v *= _control_fold(u)      # VALUE_STUN_FOLD / VALUE_SILENCE_FOLD
      score += v                      若 u 是我方（ENEMY 阵营）
      score -= v × PLAYER_VALUE_MULT  若 u 是对面（默认 1.25）

   ★★ "身价自动扣除"就在这里：循环开头是 `if not u.alive: continue`
      ⇒ 单位一死，它那一项**整项消失**（不是加一个"阵亡分"，是求和里少了一项）
      · 对面单位死 ⇒ 那个 −v×1.25 消失 ⇒ score 自动 **+v×1.25 ≈ +22~26**
      · 我方单位死 ⇒ 那个 +v     消失 ⇒ score 自动 **−v      ≈ −15~−22**
      · 骷髅兵身价恒为 0（`_unit_value` 里直接 return 0）⇒ 它死不掉分

④  血量账（本回合伤害）
      score -= Σ_我方 掉血 × HP_VALUE_W × wgt
      score += Σ_对面 掉血 × HP_VALUE_W × wgt
      · 掉血 = hp0（回合初血） − max(hp, 0)；只统计 hp0 > 0 的单位
      · wgt = 1.0，除非开了 VALUE_IMPORTANCE_POW（= (身价/基准)^p，**实测为负，已废弃**）

⑤  score += sim.killed_players × KILL_BONUS                       # 本回合击杀对面人数（生产 38 / 噩梦 0）

⑥  score -= SELF_DEATH_W × ( k×b + k(k+1)/2 )                     # 我方本回合阵亡罚
      k = 本回合新阵亡数，b = 回合前已阵亡数（生产 4.0 / 噩梦 0）

⑦  score += _position_score(sim)                                  # 位置层
      = Σ_我方单位： 若"本回合全力也够不到任何敌人" → −(near − (emove+range)) × ENGAGE_PULL_PER_CELL

⑧  score += _rule_b_score(sim)                                    # 规则 B（默认关 = 0）
      = −Σ_我方 max(预期挨打 − MOVE_ACCEPT_DAMAGE, 0) × 1.0
        + EVADE_NETWORK_BONUS × (路网够不到我的敌人数)
        + NEXT_TURN_THREAT_W × (我下回合能威胁的目标数)

⑨  score += _threat_forecast(sim)                                 # 下回合交换预判（唯一"怕挨打"的项）
      = Σ_我方 [ 若 预期挨打 ≥ 当前血 → −身价(u) × THREAT_DEAD_FOLD ]
             + [ 若 非必死           → −THREAT_INCOMING_W × 预期挨打 ]
      + 【新·默认关】 − RISK_W × max_我方( 预期挨打/血量 × 核心系数^RISK_CORE_POW )

⑩  score += FOCUS_FIRE_WEIGHT × Σ_对面 frac²                       # 集火（中间层唯一梯度）
      frac = 本回合对该目标打掉的血 ÷ 它回合初的血

⑪  score += FOCUS_TIMES_WEIGHT × Σ_对面 (hurt_times − 1)   （仅 hurt_times ≥ 2）

⑫  金矿（只对 can_pickup_gold 的单位 = hero_42 黄金矿工）
      score += gold_taken × GOLD_TAKE_VALUE(_LOW)
      score += max(GOLD_NEAR − 距离 × GOLD_NEAR_PER_CELL, 0)
      （6 个 GOLD_* 键**只走 `hero_42` 段**，不在通用表里）

⑬  score += sim.buff_taken × BUFF_TAKE_WEIGHT                     # 吃道具（按阵营定符号）

⑭  搏命激励（**写死，无键**）：
      对每个"本回合攻击过 **且** `_was_doomed`"的我方单位 → score += 6.0 + eatk × 1.5

⑮  【新·默认关】score += TERMINAL_W × _terminal_value(sim)         # 终局项（判负线凸曲线）
      我方存活 3/2/1/0 → 0/−10/−100/−1000 ；对方存活 3/2/1/0 → 0/+10/+100/+1000

return score
```

## 二、公式里每个细分项的意义（含"谁在调它"）

| # | 项 | 意义（行为上在干什么） | 谁在调 | 量级 |
|---|---|---|---|---|
| ① | 障碍绕路 | 只惩罚"真的被墙挡住"的绕路 ⇒ 拆掉挡路的墙才有收益 | `OBSTACLE_DETOUR_WEIGHT`(4.0，已建议写死) | 0~几十分 |
| ② | 阵亡计数 | 只统计**本回合新**阵亡（老死的部分是常数、对决策无用） | 写死 | — |
| ③ | **身价** | **打谁 / 保谁**：对面身价越高 → 那一项负得越多 → 打它收益越大；我方身价越高 → 越愿意为它让位/加盾/治疗 | `VALUE_SOLO_W`(1.0) · `VALUE_RELATION_W`(0.6) · `HERO_VALUE`(按英雄，可选) · `PLAYER_VALUE_MULT`(1.25) · 折减两键 | 单人数 **15.2~21.9**，对面 ×1.25 |
| ③' | **自动扣除** | **击杀的"最大一笔收益"**：单位一死整项消失 | **无键**（结构） | 对面 −→ 自动 **+22~26**；我方 → **−15~−22** |
| ③'' | 受控折减 | 被晕/被沉默的**敌人**身价打折 ⇒ 优先度下降（我方被控不折减） | `VALUE_STUN_FOLD`(0.4) · `VALUE_SILENCE_FOLD`(0.6)；**噩梦=1.0（已删）** | ×0.4 / ×0.6 |
| ④ | 血量账 | "这一下划不划算"：伤害的**线性**计价（1 点血 = 1 分，**与打在谁身上无关**） | `HP_VALUE_W`(1.0) | ±几~二十分 |
| ⑤ | 击杀奖励 | 本回合击杀的**即时**重奖（把击杀前置，避免放过必杀） | `KILL_BONUS`(生产 38 / 噩梦 0) | 38/人 |
| ⑥ | 我方阵亡罚 | 越接近判负线罚越重（凸） | `SELF_DEATH_W`(生产 4.0 / 噩梦 0) | −4~−12/人 |
| ⑦ | 位置层 | 只剩"够不着就压上"这条拉力（身份偏好全删） | `ENGAGE_PULL_PER_CELL`(1.2) | 每格 1.2 |
| ⑧ | 规则 B | 站位风险阈值 + 路网躲避 + 我方下回合威胁 | 三个键（默认全关） | — |
| ⑨ | 威胁预判 | **唯一的"怕挨打"**：会被打掉 → 按身价罚；挨打血点 → 线性罚 | `THREAT_DEAD_FOLD`(0.5) · `THREAT_INCOMING_W`(0.12) · 新 `RISK_W` | 十几分 |
| ⑩ | 集火 frac² | **中间层唯一**区分"3+3 分摊 vs 6 压一人"的梯度（身价/血量账在中间层是同分或常数） | `FOCUS_FIRE_WEIGHT`(30) | 最高 30 |
| ⑪ | 集火次数 | 同一目标被打 2、3 次的额外奖励（**边际符号反**：打死那一手反而丢分） | `FOCUS_TIMES_WEIGHT`(5.0) | 5/次 |
| ⑫ | 金矿 | 矿工吃矿重奖 + 没吃到时按距离给梯度（滚雪球） | 6 个 `GOLD_*`（只在 `hero_42` 段） | 26/34/4… |
| ⑬ | 吃道具 | 主动绕路吃有用道具（按阵营定符号） | `BUFF_TAKE_WEIGHT`(3.0) | ×道具价值 |
| ⑭ | 搏命激励 | "逃不掉且必死"的单位死前也要打出去（防空转） | **写死 6.0 + 1.5×eatk** | 6~十几 |
| ⑮ | 终局项 | 判负线意识（"再死一个就输" / "对方剩 1 个要收掉"） | `TERMINAL_W`（新，默认关） | 10/100/1000 |

## 四、身价那三项到底是怎么算出来的

```
_unit_value(sim, u)：
  solo     = DataRegistry.hero_strength(hero_id)      # 角色列表"总评分"（否则 atk×2.2 + hp×0.45 + 词条）
  synergy  = Σ_队友 DataRegistry.synergy_bonus(我, 队友)
  counter  = Σ_对面 counter_bonus(我, 敌) − Σ_对面 counter_bonus(敌, 我)
  身价 = solo × VALUE_SOLO_W × HERO_VALUE(hero_id) + (synergy + counter) × VALUE_RELATION_W
```
**实测分布**（只读探针 `RL/harness/身价探针.tscn`，49 英雄 / 2352 有序对 / 8 支队）：
- `solo` = **15.20 ~ 21.90（1.44×）**；**队内**常常只有 1.01~1.23×（F 队 18.60/18.80/18.85）；
- `synergy` 只有 **13.1%** 的配对有值（最大 5.0、常见 1.0）；
- `counter` 只有 **1.7%**（39 条，全部 +2.00，**无一负项**）。

⇒ 结论（§14#107）：**身价在中间层是"状态常数"（候选之间恒等、差值为 0），只在"击杀那一刻"以阶跃兑现**；而且它的**区分度只有 1.44×**。这就是"身价一点都不重要"的机制原因。
