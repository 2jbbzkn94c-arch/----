### 2.3 架构事实：RL 侧没有实现任何游戏规则

RL 对局跑在**真实** `scenes/Main.tscn` 实例（`Battle` 节点）上，不是另写一套战斗内核：

- 动作入口就是真实的 `Battle._do_move(u, cell, for_enemy)`（`src/Battle.gd:3036`）与 `Battle._do_attack(a, t, for_enemy)`（`src/Battle.gd:3262`）。对拍器 `RL/harness/技能对拍.gd:174,178` 直接调这两个私有方法。
- 伤害口径就是真实的 `Battle._attack_damage`（`src/Battle.gd:2492` → `Unit.effective_atk()`，含 buff / 冲锋 / 太阳斩 / 共鸣 / 远程被贴身压 1 / 麻痹 -1，见 `src/Unit.gd:425-435`）。
- 技能由**真实的** `heroes/*.gd` 执行：`Battle._hero(u)`（`src/Battle.gd:3611`）→ `HeroRegistry.create(hero_id)`；钩子派发点全在真实 Battle 里（`on_move` `src/Battle.gd:3725`、`on_turn_start` `:3731`、`on_turn_end` `:3743`、`on_enter` `:3753`、`on_died` `:4266`、攻击后 `_trigger_on_attack` `:3650`、冲锋结算 `_charge_pending` `:3201-3204`、替队友扛伤 `_bulwark_absorb` `:3593`）。
- `RL/ai/AI_Battle.gd` **不是**游戏规则，只是「AI 怎么决策」的副本：它把局面快照（`BattleSnapshot.collect`）转成自己的 `sim.units` 结构，用来**预判**「我走这步会怎样」。预判错了，AI 就会按错误预期选招。

### 2.4 边界声明：规则 = 现行版本

- **规则基准 = 仓库现行版本**（`src/` + `heroes/` + `autoload/` 的 HEAD 状态；`git status --short` 证明其未被本次审计触碰）。
- 与现行版本的差异**只存在于「AI 的预判」这一层**，即 `RL/ai/AI_Battle.gd` 对真实结算的复刻/近似。该层现在已对齐：203/203 场景（含 7 个手工针对性场景）逐字段相同。
- 换言之：RL 训练时 AI 看到的「后果预测」与游戏真打出来的「后果」一致。本报告**不主张**游戏规则本身有任何改动，也**不主张** `src/BattleAI.gd` 被改过（哈希已证明它没被改）。
- 必须同时声明的诚实边界：对拍只覆盖**被这 203 个场景触发、且被 dump 字段观测到**的东西。见第三节 B 类——有 **27 个**英雄的核心效果进不了这 4 个动作，它们的对齐**没有被本次对拍证明**。

## 三、任务 B + C：49 英雄逐条核对表

### 3.0 判定口径（先说清楚，避免含糊）

**「描述一致性」三档**
- **一致**：描述里的关键短语（时机 / 范围 / 数值 / 条件）都能在脚本里找到对应实现，且没发现与描述冲突的行为。
- **不一致**：描述的时机 / 数值 / 条件与代码实质不同（写清「描述说什么、代码做什么」）。
- **无法判定**：描述缺失（JSON「技能」列为空），或描述过简、含未定义词（如「附近」「令」无主语时机）导致无法与代码严格对齐。

**「对拍覆盖」二档**（问的是：该英雄的技能效果**能否被** 4 个通用动作 + 7 个特殊场景触发并观测到）
- **✅ 已覆盖**：效果在 `出招 / 出招·距离2 / 移动 / 被攻击`（或 7 个特殊场景）中会**真实触发**，且被 dump 的比对字段（HP / 攻 / 移 / 状态 / 位置 / 炸弹 / 墓碑 / 障碍 / 金矿 / 阵亡数）观测到。表中写明**是哪个动作**测的。
- **⚠️ 未覆盖**：效果在这些场景里**根本没触发**（条件不成立），或触发了但**没有任何比对字段能观测到** → 它对 203/203 的 MATCH **零贡献**。写明**为什么测不到**、以及**要测它需要什么场景**。

**4 个通用场景的固定布局**（`RL/harness/技能对拍.gd:95-112`）：被测英雄 X 在 `(2,4)`，假想敌 `hero_13 独脚龟` 在 `(2,3)`（同列相邻，40/40 满血）；X 被压到 `max_hp-3`（"受伤"态，用于触发"血量比较/受伤才生效"类条件）；X 的移动目标 `(2,5)`（同为同列直线相邻格）；距离2 变体把 X 放在 `(2,5)`。

**本表用到的两个距离事实（board 为 odd-q，`HexGrid` 轴向距离）**：
- `(2,4) ↔ (2,3)`：同列相邻，**距离 1**。
- `(2,5) ↔ (2,3)`：同列**相隔 2 格**。
- 因此「移动」场景里 X 走到 `(2,5)` 后，**与假想敌的距离变成 2** —— 所有"相邻"类移动后技能（烛火 / 雪拳 / 医护兵）在这套布局下都**不会触发**。

**判定链上的关键真实门控**（解释"为什么没触发"时反复用到）：
- 沉默 / 眩晕 → `Unit.skill_allowed()`（`src/Unit.gd:458`）为假，**所有技能钩子都不触发**（`_trigger_on_attack:3659`、`_bonus_damage:3622`、`_counter_bonus:3629`）。
- 远程被贴身（有敌人相邻）→ **命中附带状态不生效**（`Battle._add_status_msg:3668`）且**攻击后技能效果不触发**（`_trigger_on_attack:3661`）。
- 圣盾挡下整次攻击 → 伤害归零、该次附带的状态也不生效（`_shield_block_status`，`src/Unit.gd:76`、`_add_status_msg:3668`）；纯状态施加可 `pierce_shield=true` 穿盾。
- 后勤 → **不能主动攻击**（`Battle._can_actively_attack:2496`），"出招"对这些英雄是空操作（但仍能反击）。

### 3.2 分组小结

#### A. 不一致清单（描述说什么 vs 代码做什么）

**A1. 实质性的描述 ↔ 实现不符：1 处**

1. **hero_28 古灵精怪 —— 触发时机不符（唯一实质不一致）**
   - 描述：**「对方回合结束时」**随机变为己方队伍中的一名其他角色，暂时获得其所有技能和特性，直到下次变化。

**A2. 行为一致但实现位置违反项目自身架构：1 处**

**仍无法对拍的原因（hero_45 坠炮手）**：它的核心特例是"**射程/视线**"——全场射程 99、弹道无视障碍/单位/墓碑、被贴身时射程退化并受嘲讽吸引。
但对拍器的动作入口是 `Battle._do_attack(attacker, target, for_enemy)`，它**不校验射程与视线**（射程/视线由选择层 `_compute_ranges` 与 AI 目标筛选实现）。
所以无论把目标放多远、中间塞多少障碍，"真实结算"都会照打，两侧必然一致 → 这类场景只会产出假绿，本轮**不构造**。
要真正对拍需要换一层入口：比对"真实选择层算出的可攻击格集合"与"AI `_actions_for` 生成的候选动作集合"（新的比对维度，不在本次范围内）。

**另一处仍无法对拍的边界（不单独计数，已在表里标注）**：8 个回合边界技的"跨回合到期"本身——
AI 只模拟本回合内我方行动，回合切换不在模拟范围内，所以"AI 能否预判回合开始/结束技的上下场"这个问题对拍回答不了；
本轮能验证的只是"**回合技的成果被快照完整带入 AI 视野**"（`SNAP`，14 条）以及"完整回合循环后局面读取一致"（`SNAP·回合循环`，49 条）。
