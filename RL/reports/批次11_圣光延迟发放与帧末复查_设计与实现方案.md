## 2. ⑤ 的实现方案（复用 `pending_vanish / _sim_flush_pending` 模式）

### 2.1 数据结构
- `Sim` 增：`var pending_guard: Array = []` —— 元素 `{ "dst": SimUnit, "giver": SimUnit }`（"已占位、待发出"的盾）。
- `Sim.clone()` 增：`c.pending_guard = pending_guard.duplicate()`（与 `123` 行 `pending_vanish` 同款）。

### 2.2 触发侧改造（`_sim_maybe_guard`，`2025-2043`）
```
① wounded.shield / not wounded.alive → return        （保持 2033-2034）
② wounded.fn == sim.active_fn → return               （保持 2035-2036）
③ 找到发放者 g：alive + 同阵营 + hero_22 + 未沉默/眩晕 + not aura_used   （保持 2039）
④ g.aura_used = true                                  （占位，保持 2041）
⑤ 不再立刻 wounded.shield = true；改为：
      sim.pending_guard.append({ "dst": wounded, "giver": g })
```
即：**占位立即、发盾延后** —— 与真实"先占位挡同帧双发、帧末才 add_status"一致。

### 2.3 落盘侧（`_sim_flush_pending`，`1407-1411`，在 `_apply` 的三个出口 `1250 / 1265 / 1401` 已被调用）
在**处理完 `pending_vanish` 之后**（让"本动作内的阵亡"先落定）逐条复查：
```
for e in sim.pending_guard:
    dst = e.dst ; g = e.giver
    ok = dst != null and dst.alive and g != null and g.alive \
         and dst.fn == g.fn and not dst.shield \
         and not g.silenced and not g.stunned
    if ok: dst.shield = true
    else:  g.aura_used = false      # 名额退还（③ 的"真正发出才算"）
sim.pending_guard = []
```
- 复查项与真实帧末一一对应：单位已死/失效 → `dst.alive`/`g.alive`；已不再是队友 → `dst.fn == g.fn`；此刻已有盾 → `not dst.shield`；下一帧被控 → `not g.silenced/stunned`。
- **`aura_used` 允许回退**：这是与现版最大的语义差别（现版置真后永不回退）。
- 与 `clone()` 的配合：`pending_guard` 在搜索里随节点复制 ✓；beam 里"尚未 flush 的中间态"不会被评估（`_evaluate` 只在节点结束时跑 ✓）。

### 2.4 预期连带效果
- **⑤a（§1 窄差异）应当一并消失**：盾改为动作末尾才落，则"烛火移动灼烧 → 随后出招"这类**两次动作**的情形与真实一致（真实在两次动作之间有整帧，盾早已发出）；而"同一同步块内二次伤害"（宿魂镜像 + 长剑剑气同招命中同一目标）也变成"整招结束才发盾" → 与真实帧末同构 ✓。
- 需要同步更新的注释：`2030-2032`（现写"立即发盾的粗粒度模型"）与 `RL/reports/已知窄差异与场外界线_登记.md §1`（该条应从"不修"改为"已由批次 11 收掉"，附验收证据）。

## 5. 未决/风险

- **粒度**：真实是"帧末"，本方案是"动作末尾"，二者在"一次动作内多次受伤"上等价、在"跨动作"上一致（真实帧早已过去）；唯一残留差异是"**同一动作内、发盾之后再受伤**"这种更细的同帧竞争，登记为待观察（预计极罕见，且方向与现版相反）。
- **顺序**：flush 必须在 `pending_vanish`（阵亡落定）之后，否则 S3 会误发盾。
- **不动的东西**：`src/`、检视器、`位置/有效移/冻`族（按指示本轮不动）。
