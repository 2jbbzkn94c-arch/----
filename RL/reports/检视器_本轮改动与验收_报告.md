## 0. 对拍块内容修正（第 3 轮：预测侧恒"无" / 幻影地形 / 判定自相矛盾）

1. **"出招前"快照取错时机** —— 原来在 `_call_action` **之后**才 `_snap_of(before, view)`，而 `_snap_of`
   按 view **现取字段**，于是"前"拿到的是出手后的状态 → 单位段恒"无变化"；地形字典被误用 → `0→3` 幻影。
   现在两份"前"快照都在出招前冻好：预测侧 = 前→预测局面，实际侧 = 前→出招后，两侧共用同一份"前"。
2. **预测侧恒"无"的真根因（与调用顺序无关）** —— `_predict()` 里 `_ai._apply(sim, idx, a)` 是**原地修改** sim，
   返回的 `pred["sim"]` 就是**同一个对象**；调用方再 `_snap_sim(pred["sim"])` 永远拿到"预测后"状态 → 两次快照相同。
   **修法（已批准并实施）**：在 `_predict()` 内部、`_apply` **之前**先 `_snap_sim(sim, descs)` 存为 `sim_pre` 一并返回，
   调用方直接用 `pred["sim_pre"]` —— 与调用顺序彻底解耦。
   - **顺带核实（决定"能否用同一对象做前后对比"）**：`RL/ai/AI_Battle.gd` 的 `Sim.clone()` **是深拷贝**：
     `units` 逐个 `SimUnit.new()`，五个单位/地形 dict 全部 `duplicate()`；仅三张**只读派生缓存**
     （`walk_cache`/`walk_cache_pass`/`soft_cache`）共享引用（注释：地形一变由 `_apply` 清空）。
     所以结论是"同对象不能做前后对比，必须在 `_apply` 前快照"，而不是靠 clone。
3. **判定与展示自相矛盾** —— 判定改为**由块内两侧展示直接推出**：两侧逐条相同 → `MATCH（两侧逐项一致）`；
   有一条不同 → `DIFF` 并给出第一处不同的"预测 X / 实际 Y"。字段级 `diffs=[...]` 另起一行附上。
4. **快照有效性校验** —— `_snap_invalid_reason()`：缺地形五键或预测侧 sim 缺失时**拒绝列项**（打印"快照无效"），不印幻影。
5. **`String(<Variant>)` → `"%s" % v`**（本项目 `String(<Object>)` 会报 `Nonexistent 'String' constructor` 并返回 null）。
6. **快照单位的键改为 view 下标字符串**（`_ukey(k)` → `"u0"`…）：对象作 Variant 键在这里不可靠
   （实测 `_by_key()` 只剩一项 → 逐单位对比恒"无变化"）。两侧都用同一 `view` 下标生成键，**同源同序**。

**实测（`--selftest 3`，退出码 0，cmd 重定向捕获）**：预测侧与实际的 AOE 逐目标完全一致
（烛火移动后灼烧 3 个敌人各 -3 + 自己换格，两侧逐条列出），判 `MATCH（两侧逐项一致）`；
道具被拾取的招判 `DIFF：预测 地形/道具：无变化 / 实际 道具 (2,4)（被拾取）`。控制台共 21 个对拍块，
除引擎自身证书报错外**无任何自有输出**。

**编译期崩溃判据（已转告用户自查）**：`var pairs := [["obstacle","障碍",true], ...]` 这种
"`:=` 推断 + 元素类型不一致的嵌套数组字面量"会让本项目 Godot 直接 signal 11（无任何报错）；
改平铺数组 + 显式 `: Array` 即恢复。

**退出告警：已定案，根因不在本 harness**。`--verbose` 实测：
```
Leaked instance: AudioStreamWAV:… - Reference count: 1
Leaked instance: AudioStreamPlaybackWAV:… - Reference count: 1
Resource still in use: res://assets/audio/turn.wav (AudioStreamWAV)
```
即**音频资源与播放对象**被持有到进程退出。该音效由 `AudioManager` autoload 播放
（`Battle._begin_side` 里的 `AudioManager.play("turn")`），**不在 harness 可控范围**；
按"不许改 `src/`"的要求到此停手。（已排除自身因素：在 `_exit_tree()` 显式 `flush()+close()`
运行时日志句柄后告警无变化。）

**反击覆盖（已补齐）**：默认阵容下 AI 对局**撞不到反击**——触发条件苛刻
（`src/Battle.gd:3363-3375`：被打者存活 + `can_attack()` + `effective_atk()>0` + 本回合未反击过 + 距离≤1），
而 AI 优先收残血/打必杀，剩下的近战互殴又常被打死。为此加了命令行取证开关 **`--demo-counter`**：
把一个敌方单位挪到紧贴当前行动方，然后**走 `_step()` 同一条报告链路**执行一次攻击，
于是块里同时出现"被打者掉血"与"攻击方被反击掉血"。实测（`--selftest 3 --demo-counter --pai 1`）：
```
[对拍] #1 第1回合·我方  医护兵(hero_06)#3  攻击 独脚龟(hero_13)#0
  预测 | 独脚龟(hero_13)#0：HP 33→30（-3）
  预测 | 医护兵(hero_06)#3：HP 16→14（-2）      ← 被反击
  实际 | 独脚龟(hero_13)#0：HP 33→30（-3）
  实际 | 医护兵(hero_06)#3：HP 16→14（-2）；有效攻 3→1
  判定 DIFF：医护兵(hero_06)#3 有效攻 预测3→实际1
```
该 DIFF 是**真实缺口**（真实侧攻方有效攻被降到 1、模拟未跟上），如实上报、未掩盖。
