## 训练口径（2026-09-19 用户定，这就是"英雄特化"怎么训）

> 用户原话：「被训练的队伍用噩梦+最新权重，陪练队伍用噩梦+上一个权重。只要最新的权重对上一个权重胜率能不断增加，
> 最终到达一个边界，是不是就能找到相对更强的权重？还有你训练某个英雄的时候，其他英雄不要被正在训练的权重影响了，
> 要控制变量」「为什么要那么多种子？**以测试权重和不同队伍为主**啊。其他几个英雄训练起来」

| 要素 | 做法 | 为什么 |
|---|---|---|
| 上一代 | `RL/weights/英雄世代.json` = 当前生产 `噩梦.json`（**通用键 + `hero_XX` 英雄段**，2026-09-20 并档后是同一份文件） | 起点必须是"线上现在跑的"，否则不算改进 |
| 候选 | 上一代 + **一个英雄的若干键**（一次一个臂） | 单变量：其他英雄一个键都不动 |
| 陪练 | 上一代**本身**（`league.checkpoint` + `self_play_fraction=1.0` → harness 的 `wB` 通道） | 用户口径的"新 vs 旧" |
| 盘面 | **镜像同队伍**（双方同一支队） | 双方唯一差别就是那几个键 |
| 队伍 | **多支**（每个臂在 3~6 支不同队伍上各打一遍） | 用户口径：看的是"换队伍还成不成立"，不是堆种子 |
| 指标 | 生产侧（`a_side=1`）胜率 + **配对 Δpts**（同 种子×先后手×队伍，臂 − 恒等对照臂） | 绝对分会被"这批种子整体偏难"吞掉，配对差才是键的效果。⚠️ **只有 `a_side=1` 的那一局带信息**：`a_side` = **候选（A）扮演的阵营**（`RL/harness/对局.gd:106`）⇒ `a_side=0` 时候选控的是**固定玩家牌组**，英雄专属键若该英雄不在那副牌里（宿魂就是），这些局**结构上不可能有差**（2026-09-21 实测：60 个非生产侧格子里 **59 格两臂逐位相同**，唯一不同的那格差 0.3 分 = 搜索墙钟预算造成的重跑抖动）。配对一律只取 `a_side=1` |

## 英雄AI对拍（AI 预测 vs 实际发生）—— 2026-09-23 新增

**什么时候跑**：① 新加了一个英雄 ② 某个英雄的技能效果改了 ③ 怀疑 AI 对这英雄的估价与真实战斗不一致。

**怎么跑**：双击 `Data\Hero\Bat\英雄AI对拍.bat` ⇒ 输入英雄（`30` / `26,22,30` / `26-30` / 名字如 `嬉皮死神` / `all`）⇒ 选跑法（1 快 / 2 标准 / 3 彻底）。脚本本体在 `Data\Hero\Source\英雄AI对拍.ps1`（工具位置见 `1_通用策略.md` 的版本锚点表）。免菜单写法：`-Heroes 30 -Mode quick`、`-All -Mode quick -Force`、`-List` 只列名单。

**它跑什么**（判定器是 `Data\Hero\Source\verify_heroes.ps1`，bat/ps1 只是中文外壳）：

| 层 | 场景 | 看什么 |
|---|---|---|
| L1 静态 | 无（读文件） | 英雄脚本在不在 · `heroes\HeroRegistry.gd` 注册没 · 角色表里有没有 · 矩阵有没有它的专用臂 · `噩梦.json` 里 `HERO_VALUE` 配了没 |
| L2 技能对拍 | `RL\harness\技能对拍.tscn` | 逐技能逐案例：**AI 预测的结算 vs 真实战斗的结算**（MATCH / DIFF / SKIP / SNAP） |
