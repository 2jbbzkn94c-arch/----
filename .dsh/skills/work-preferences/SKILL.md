# 战旗项目 · 工作偏好

## 核心约定

1. **不要主动写测试**：改完代码不要顺手新建 `tests/*.gd` / `*.tscn`。用户明确说「写个测试」时才写。
2. **不要主动跑测试/回归**：不要为了自证正确去批量跑 `tests/` 下的用例。用户明确说「跑一下回归」时才跑。
3. **用户自己先测**：他跑游戏验证，有问题会带着现象回来；那时再按需定位、修复。
4. **交付只说三件事**：改了哪些文件、改了哪几处行为、怎么手动验（点哪里、看什么现象）。
5. **不做未被要求的额外改动**：不顺手重构、不加调试日志、不主动改文档；不自动 `git commit`。
6. 用中文回复，简洁直给。

## 为什么

用户觉得“每个小改动都配一堆测试 + 跑一大串回归”很浪费时间，验证环节他自己能做得更快。
